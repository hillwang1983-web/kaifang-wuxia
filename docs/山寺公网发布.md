# 山寺公网试玩

山寺与青石渡使用同一看板账号登录，入口、入场票据和运行目录相互独立：山寺 `/shansi/`，青石渡 `/qingshi-v04/`。这是第一里程碑，单人加 AI 净心，部分场景、角色和招式特效仍为占位。

## 构建

安装官方 Godot **4.7.2 stable** 和同版本的 Web 导出模板（`web_release.zip` 与 `web_debug.zip`）。核对官方 `SHA512-SUMS.txt`；不将引擎、模板、导出包或本机路径提交 Git。

```sh
npm ci
npm run test:all
GODOT=/absolute/path/to/godot npm run build:shansi -- --commit HEAD --output /absolute/path/to/new-release
npm run test:shansi-web -- --release /absolute/path/to/new-release --gateway /absolute/path/to/wind-game-gateway --output /absolute/path/to/acceptance-logs
```

输出目录必须不存在。脚本从指定 Git 提交归档源码，导入资源，执行全部 Godot 规则测试，执行 `auto quit` 通关冒烟，再做单线程 Web 导出。首次导入只在临时副本取消主题的前置加载，避免字体缓存尚未生成；随后按字节恢复原项目设置，规则测试、通关和导出都使用原始主题。非零退出、脚本错误、没有“自动试玩结算”均停止，不生成成功回执。产物含 `app/` 和 `runtime-manifest.json`，后者记录精确提交、引擎版本及所有服务/资源文件的 SHA-256。`app/server.mjs` 仅监听 `127.0.0.1:8797`。

青石渡更新脚本仍使用原有锁、测试、备份和失败回退；大仓库改为 Git 直接写临时 tar，再解包，避免 stdout 的 64 MiB 上限。

## 看板接入

`portal-integration/gateway-shansi.patch` 是对独立 `wind-game-gateway` 工程的最小补丁，包含新卡片、路由和测试：

```sh
git apply --check /path/to/kaifang-wuxia/portal-integration/gateway-shansi.patch
git apply /path/to/kaifang-wuxia/portal-integration/gateway-shansi.patch
npm test
```

看板环境变量增加 `SHANSI_ORIGIN=http://127.0.0.1:8797`，保留原有游戏配置。山寺静态服务从根路径提供文件；网关去掉 `/shansi` 前缀。只有山寺允许 `wasm-unsafe-eval`，并将单个代理资源上限设为 128 MiB；旧游戏保持原有 CSP 和 16 MiB 限制。山寺通过 `JavaScriptBridge.get_interface` 读取网址参数，无须放开 JavaScript `unsafe-eval`（[Godot 官方接口说明](https://docs.godotengine.org/en/stable/classes/class_javascriptbridge.html#class-javascriptbridge-method-get-interface)）。继续使用现有登录、单次入场票据、路径隔离 Cookie、退出撤销，不增加账号接口。

## 发布与验收

先备份将修改的源文件、运行文件与 LaunchAgent，再持有服务更新锁。首次安装使用独立山寺服务目录；后续替换先备份旧 `app/` 与清单，复用 `scripts/update-preview.mjs` 导出的 `publishRelease` 执行切换和失败回退。不要覆盖账号库或青石渡服务。LaunchAgent 环境变量变更须重新加载配置；`bootout` 后的卸载可能仍在进行，`bootstrap` 应有界重试并验证健康，回退旧配置时同样处理。重试启动不能代替测试、资源哈希或公网检查。

启动山寺后，用 `scripts/build-shansi-preview.mjs` 的 `verifyShansi(manifest, base, app)` 核对健康提交、每个磁盘文件和全部 HTTP 资源哈希。再启动看板配置，验证：

- 未登录 `/shansi/`、`index.wasm`、`index.pck` 跳转到 `/login?game=shansi`，青石渡保持原有登录拦截。
- 使用内存账号库验证看板两张卡片、票据独立、WASM 类型/大小、CSP 和退出撤销。
- 通过真实导出包和同样的网关鉴权流程启动浏览器，观察游戏画面、资源请求与控制台。
- 记录退出码、构建/浏览器日志、提交号、清单、备份与发布时间。失败恢复本次变更，验证旧服务；首次安装失败撤回新增入口。

自动通关与桌面浏览器启动不代表实体手机、手柄或人工完整流程已经验收。

Web 自动通关验收覆盖出身开场、山门、藏经阁和大雄宝殿，等待结算的上限为 600 秒。三段流程约需 200 游戏秒，浏览器软渲染可能更慢；超过上限、没有结算标记或出现脚本 / 页面错误仍明确失败，不发布。
