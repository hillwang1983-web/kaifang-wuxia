# 青石渡风波 V0.4

原创单人武侠章节：取药 → 查账 → 渡口冲突。第一幕就是原先的单文件《渡口失药》，2026-10-23 已并入本目录，不再另有试玩版本。画面已更新为松风 clear1：NPC 与战斗人物共用身形，场景采用原创图集 `assets/songfeng/world-atlas.png`。历史 Ninja Adventure CC0 资源及许可证保留于 `assets/na/`。

在仓库根目录运行 `npm run serve`，打开 http://127.0.0.1:8793/qingshi-v04/ 。服务只监听本机，只发布游戏资源。测试与多终端协作的统一命令见根目录 `README.md`。页面不依赖外部字体或网络接口。

## 操作

- 电脑：WASD / 方向键移动，J 普攻，K / I 两个主动招式，空格闪避，E 交谈，H 包扎，M 打开江湖图与武学。
- 手机：横屏，左侧摇杆，右侧按住普攻连续三段，双主动招式/闪避，靠近人物后点交谈。右上角可用绷带，战斗外使用。
- 武学：在手记中从松风剑气、追风刺、截流剑、回澜斩中带两招，新局默认剑气与截流。战斗外可换招，换招不重置槽位冷却。
- 剑饰：找周砚制作破势或回气。前者强化打断后的反击窗口，后者每次有效剑招最多返还一次内力。
- 地图：江湖图显示位置、人物与当前目标；地图不自动移动。山道南侧可绕路，有可搜寻的旧行囊。

## 章节

先找沈青接下取药请求。武力夺药与采草交换都能完成；取药后可翻阅匪营东面的工钱账册。

交药只是第一幕结束。许舟的亲历证词、货车残单与账册是三种有来源的线索。向沈青作出下一步决定：公开账目、促成调停或离开。确认前可继续调查；不找齐线索也能完成。

决定之后到渡口南面的告示附近赴约。公开会失去陆平补给，但争取船工的实际战斗支援；调停保留匪首合作，交换取药且掌握两条线索时可凭证据议和；离开可领两条绷带，但要独自应对余匪。未领取的帮助不会写成已领取，未参战不会写成战斗支援。

结局后可继续逛、换招、切磋。新局不会继承旧局抉择。只使用 `qingshi-chapter-v04` 本地存档，不读取或清除旧单文件版的 `duko-save-v3`。

## 文件和验证

- `index.html`：页面、手机布局与控件。
- `game.js`：原型画面、输入、战斗、剧情对话及恢复。
- `chapter.js`：共享章节规则和存档事务，可直接用 Node 测试。
- `原版校验.json`：实施前四个原文件的 SHA256。
- `验收记录.md`、`自动验证结果.json`：本次检查及明确的证据边界。

在仓库根目录运行 `npm test` 检查规则、采样与 HTTP；首次浏览器测试先运行 `npm ci`、`npx playwright install chromium`，再运行 `npm run test:all`。用例自动使用临时端口和隔离浏览器存档。`?debug` 才暴露 `window.__duko`；完整剧情用例使用调试定位及加快攻击，不代表自然操作难度或时长已验收。历史验收文件保留原始证据边界，不能替代当前复测。

## 2026-10-23 声音入口与背景音乐（#7）

开始界面明示「声音：关（点此开启）」，玩家的选择存 `localStorage`（`qingshi-sound`），刷新后沿用；首次进入仍默认静音。右上角「音」按 AudioContext 实际状态显示开 / 关 / 停：浏览器未放行或切后台挂起时显示「停」，点一下恢复，不显示假成功。

新增 `songfeng-music.mjs`：背景音乐全部用 Web Audio 现场合成，不含外部音频素材，无许可问题。探索段为 D 羽调五声音阶拨弦旋律加低持续音（约 72 拍/分），战斗段为鼓点、低音反复与笛声短句（约 116 拍/分）；进出战斗交叉淡入淡出，预警与命中时音乐短暂压低。手动暂停、切后台或静音时立即停止排音符。静态服务与发布脚本白名单已加入该模块。自动化只校验音频状态，实机听感需真机确认。

交互提示音（#7 第 3 步）：拾取（木料堆、止血草、药包、行囊、补给、切磋得料）、购买、锻造剑饰、记下线索、完成（交药、抉择、结局）各有一段落在 D 五声音阶上的短句，不再一律用金币声。同一帧重复的提示音只播一次，同一提示音 60ms 内不重播；命中声每帧只取最重的一下。敌人预警音提高一个八度并加大音量，播放预警、命中与交互提示音时背景音乐压低约 14 dB，同一录音链路下预警音高出让路后的音乐约 8 dB。

## 2026-10-23 第一轮战斗调整（拉长时长）

10-23 那局手机试玩，从开局到结算实际只操作了 79 秒，匪首 3.5 秒就倒了，一次重劈都没打出来。这一轮只改战斗，探索门槛和地图等复测之后再动；目标是单人首通 20–30 分钟。

- 普攻三连 20 / 24 / 34 → 10 / 12 / 18。剑招伤害不变。
- 血量：匪首 240 → 800，匪徒 45 → 80，弓手 60 → 80，护院 90 → 140，护院头领 180 → 360。匪首重劈伤害 28 → 35。
- 架势：匪首和护院头领平时只吃一半普攻伤害。两种情况会让他们失衡 2 秒（破势再加 0.8 秒），失衡期间普攻吃满：一是被剑招打断蓄力；二是重劈出手前 0.5 秒内闪避，不论是用无敌帧硬闪还是闪出范围。
- 匪首每次重新交手（败退之后、开始切磋）都先出重劈。
- 战斗中不再自然回内力（原来 1.5/秒）；木人桩练习仍是 1.5/秒，脱战 6/秒。
- 试玩记录 `combat` 和每场 `battles` 新增四个字段：`windups` 敌人蓄力次数、`heavyWindups` 重劈蓄力次数、`dodges` 按下闪避次数、`evades` 有效闪过次数。旧记录缺这些字段时从 0 开始累计。导出记录的 `build` 改为 `V0.4-combat1-20261023`，和调整前的记录区分开。

用调试接口逐帧模拟三种打法打匪首：
- 只普攻、不闪避：约 11 秒败退，匪首还剩约 600 血。
- 每次都闪开：约 32 秒取胜，见到 6 次重劈。
- 闪避加截流剑打断：约 28 秒取胜。

模拟是帧级精确操作，只代表时长下限，不等于真人手感或难度；要用同一台 iPhone 正常入口复测。剧情路径用例里匪首和终局敌人血量变高了，所以用例改为保持满血并增加出手次数，它仍只验证状态链。
