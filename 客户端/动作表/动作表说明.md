# 角色动作/方向/帧序表（loginp.exe 逆向）

数据文件：`action_table.json`（同目录）。验证图：`strips\*.png`（每格标了 `d<方向> f<帧>`）。
方法：REA/Ghidra 静态分析 `maina\loginp.exe`（没运行客户端），再用 `wjres.py` 的解码函数把 `.cp` 按结论排成条带肉眼核对。
标记：**[已验证]** = 反编译 + 渲染都核对；**[代码]** = 只从反编译读出；**[推测]** = 猜的。地址为虚拟地址。

## 1. 结论摘要

* **CPn 的 n = 动作号**（action），不是方向。一个 `ROLE\<层>.CP<n>` 记录就是"该层在动作 n 下的全部方向×帧"。
* **每个 .cp 内部 = 8 个方向块，每块 n/8 帧**：`文件帧号 = dir * (n/8) + f`。**[已验证]**
* 方向 dir 0..7 = 上(背对镜头) → 左上 → 左 → 左下 → 下(面向镜头) → 右下 → 右 → 右上（逆时针，无镜像）。**[背面/正面已验证，其余代码]**
* 世界场景只有 3 个动作在用：**站立 = CP7，行走 = CP1，普通攻击 = CP4**，骑乘 = CP8(移动)/CP9(站立)。播放帧数一律 8 帧/方向。
* 帧间隔（ms）：站立 150，行走 100(obj+0xc，默认值)，其它状态 100，状态4 = 50。tick 单位按 ms 推测。

## 2. .cp 帧排布

| 项 | 内容 | 证据 |
|---|---|---|
| 文件帧数 n | 一律 64 的整倍数：CP1/CP7 = 64（8帧/方向）；boy01/02/girl 的 CP2、CP3 = 96（12帧/方向），CP4/5/6 = 120（15帧/方向）；其它模型 CP2/4 = 64（8帧/方向） | `counts` 见 JSON `availability` |
| 方向块 | 加载器只取 `[dir*n/8, (dir+1)*n/8)` 这一块帧，解压出来缓存 | `0x51fa4c` @0x521025..0x5210eb（`n>>3`，`param_6*iVar5`） |
| 缓存键 | 槽 `(model, cp, 阴影标志, dir)`，槽大小 0x2fc，当前槽号 `self+0xdaa60` | `0x51fa4c` @0x520fa3..0x520fe3 |
| 绘制取帧 | `帧表[slot+8+f*12] = (ox,oy,w,h)`，f 是**方向内**帧号 | `0x5253c8` |
| 世界场景播放帧数 | 8（所有 SetState 的 count 都是 8），所以 boy01 的 CP4 第 8..14 帧、CP2/3 第 8..11 帧世界场景不播 | `0x768370`、`0x76702c` |

验证图：`strips\boy01_CP1.png`（行走，一行一个方向，8 帧摆臂循环）、`boy01_CP7.png`（站立，轻微呼吸）、`boy01_dir4_CP2-6.png`（面向镜头一行，CP2..CP6 依次是 5 种挥武器动作）、`boy10_dir4_all.png`（B 系列 CP1/4/7/8/9/10）。

### 动作折叠（0x5253c8，传给加载器前）
1. 模型 ∈ {1, 2, 0x80}：不折叠，7 个 CP 都有。
2. 其它模型：action 3 且 模型 ∈ {6,7,8,0x84,0x85,0x86} → 2；action 5/6 → 4。
3. B/F 系列（模型 0x14..0x19、0x92..0x97）：action 2/3 → 4（它们只有 CP1/4/7/8/9/10）。
4. boy05 / girl04 没有 CP3 也不在折叠名单里（原版缺陷，世界场景用不到 3）。

## 4. 方向

* 方向号 → 屏幕朝向：0=上，1=左上，2=左，3=左下，4=下(面向镜头)，5=右下，6=右，7=右上。
* 由位移求方向（`0x767a50` → `0x767994`）：位移 (mx,my)（屏幕坐标，y 向下），令 X=-mx, Y=my，用 ±tan22.5°(=0.41421356，80 位常量在 0x767864/0x7678c4/0x767924/0x767984) 把平面分 8 个 45° 扇区得到扇区 s，`dir=(s+4)%8`。我用脚本 `dirsim.py` 对 8 个方向位移验证：上→0、右上→7、右→6、右下→5、下→4、左下→3、左→2、左上→1。
* 登录/出生时默认 dir=4（`0x768aa8` 设 `+0x5d=4`）。
* 路径行走（状态6，`0x76d768`）用 `dir=(idx<4)? idx+4 : idx-4` 直接把路点序号折成方向。

## 5. 世界场景播放时序（obj = TPlayer/NPC 对象）

| 字段 | 含义 |
|---|---|
| +0x5c | 状态：0 站立，1 行走，2 同站立，4 抛物线/击飞（50ms），5/6 特殊 |
| +0x5d | 方向 |
| +0x5e | 当前帧(方向内) |
| +0x5f | 帧数上限，默认 8 |
| +0x60 | 基础帧间隔 ms，默认 100 |
| +0x54 | 上次翻帧时刻 |
| +0xc | 行走状态的帧间隔，构造时 100 |

* `SetState(obj,state,frame0,intervalMs,count)` = `0x768370`；**状态改变时才**写 `+0x5c/+0x5e/+0x5f/+0x60`。几乎所有调用点都是 `(0|1, 0, 100, 8)`。
* 每个 tick 的翻帧逻辑（`0x76ca9c`）：`interval = state0? +0x60+50 : state1? +0xc : state4? 50 : state5? +0x60+50 : +0x60`；若 `(tick - +0x54) > interval`：`+0x54=tick; frame=(frame+1) % +0x5f`。`+0x60==0` 不动画。
* 状态→动作（`0x769fa4`、`0x769c2c`、NPC 版 `0x77208c`）：0→7, 1→1, 2→7, 4→(tick-+0x50 > +0xd0 ? 7 : 1)；mounted 时 1→8、7→9；攻击标志置位且未骑乘 → 4。
* 世界场景里**攻击动画的起始/重置点**（谁置 `+0xd4`、是否把帧归零）没追。

## 6. 层叠与锚点（给 web 复刻用）

1. 每个角色一次画：阴影(`B<n>0S`/`G<n>0S`, 加载器第5参数=1) → 身体(`M<n>0000`/`G<n>0000`/`B<n>0000`/`F<n>0000`) → 装备层（头发 `MA..`、衣 `PA..`、武器 `WA..`）。装备槽顺序：模型 3..9 为 `[0,2,1,3]`，其它 `[0,1,2,3]`，其中 0=身体，k>0 画 `equip[k-1]`（`0x5252f8`）。`strips` 用 身体→衣→头发→武器 叠出来，位置对得上。
2. 画点：`x + ox`、`y + 修正 - 56 + oy`，修正：模型3→+6、模型4/0x81→+9、模型0x82→+10、其它 0（`0x5253c8` 局部 `local_c`）。(x,y) 是调用方传入的对象屏幕坐标，具体与脚底的关系没单独验证。
3. 阴影调色板只有一色 0x1863，半透明叠加。
4. 模型号 ↔ 文件：1..8→boy01..08.mrg（身体 `M<n>0000`；boy09 为空），0x14..0x19→boy10..15（身体 `B1..6 0000`，无阴影文件），0x80..0x86→girl、girl02..07（`G1..7 0000`；girl08 为空），0x92..0x97→girl09..14（`F1..5,7 0000`，无 F6）。模型号→mrg 句柄的实际绑定是运行时的，这里按层名一致性推的 **[推测]**。动作 8/9：模型1-4/G1-3 的在 `Horse.mrg`（骑乘合成体，含 M1..4/G1..3 全套层），6-8/G5-7 在自己的 mrg。
5. 装备 id → 层名：来自内存表 `self+0x281058`（每 id 14 字节），**表的来源没追**。

## 7. 战斗场景（只到半途）

`0x954808` 是战斗角色绘制，战斗状态 byte(`+0x8c3cd`) → action：0→7, 1→1, 2→5, 3→按子状态(+0x8c45b)1→2/2→4/3→3, 4/5/6→4，0x11/0x13/0x14/0xab..0xb0 同 3；之后 `0x953c5c` 还会按战斗模式再改写（玩家自己 3→5 等）。战斗帧号/间隔由调用方传入，没追。

## 9. 如何使用本动作表（网页端 import）

**文件**（都在 `逆向工具\动作表\`，整个文件夹连同 `逆向工具\资源解析\out\` 一起拷走，相对路径才成立）：
* `action_table.web.json`：给网页端用的精简表（路径全是相对本 JSON 的）。`action_table.json` 是带证据地址的完整版，仅供查阅。
* `actiontable.js`：ES module 小库（浏览器/node 都能 import），已用 boy05 的 `atlas.json` 在 node 里跑通。
* `tools\`：生成/验证脚本（`genweb.py` 重新生成 web.json；`strip.py` 出条带图；`dirsim.py`）。

**`action_table.web.json` 字段**

| 字段 | 含义 |
|---|---|
| `directionCount`/`directions` | 8 个方向，下标 0..7 = N,NW,W,SW,S,SE,E,NE（0 背对镜头，4 面向镜头） |
| `actions.<名>` | `cp` = 记录名里的 CPn；`loopFrames` = 每方向播放帧数；`intervalMs` = 帧间隔；`battleOnly` 只在战斗里出现；`confidence:"low"` 语义未定 |
| `cpFallbackRules` | 动作号折叠规则，顺序套用（`modelIn/NotIn`、`seriesIn/NotIn`），套完该模型没有这个 CP 就不画 |
| `worldState` | 世界状态→动作：0/2 站立、1 行走；骑乘时 walk→`ride_move`(CP8)、idle→`ride_idle`(CP9)；未骑乘且攻击中→`attack`(CP4) |
| `stepRule` | 翻帧规则文字说明；`Actor.update` 已实现 |
| `layerOrder` | 层叠顺序：先阴影，再 `[0,1,2,3]`（模型 3..9 为 `[0,2,1,3]`），0=身体，k>0=装备槽 k |
| `drawOffsetY` | 画点 `y_draw = y + 模型修正 + base(-56)`，再加每帧 `oy`；x 直接加每帧 `ox` |
| `models[]` | 每个模型：`model` 模型号、`mrg` 文件名、`series`(M/B/G/F)、`bodyLayer`、`shadowLayer`(可空)、`atlas`(相对路径)、`cps` = {CP号: 每方向文件帧数} |
| `mountedRiders` | 模型 1-4 / G1-3 的 CP8/9 在 `Horse.mrg`（同名层）里 |
| `atlasPattern` | `../资源解析/out/{mrg名}/atlas.json`；这些 atlas 要先用 `wjres.py` 转换出来（目前只转了 boy05、npc101 等；要哪个模型就转哪个 mrg） |

**关键公式**
* 文件帧号 `fileFrame = dir * framesPerDir + f`（`framesPerDir = models[i].cps[cp]`），在 `atlas.images` 里取 `name == "ROLE\<层>.CP<cp>"` 且 `frame == fileFrame` 的项；找不到 = 空帧，不画。
* 世界场景 `f` 只在 0..`loopFrames-1`（8）里循环；站立 150ms、行走 100ms 翻一帧。
* 画法：`drawImage(page, x, y, w, h, 画点x + ox, 画点y + oy, w, h)`。

**JS 示例**（和 `actiontable.js` 配套，node 里用 `file:///` URL 导入）
```js
import * as A from './actiontable.js';

const table = await A.loadJson('./action_table.web.json');
const model = table.models.find(m => m.model === 5);          // boy05
const atlas = await A.loadJson(new URL(model.atlas, location.href).href);
const index = A.buildAtlasIndex(atlas);                        // 'M50000|7' -> 按帧号索引
const page  = new Image(); page.src = new URL('../资源解析/out/boy05/atlas_0.png', location.href).href;
await page.decode();
const pages = { 'atlas_0.png': page };

const actor = new A.Actor(table, 5);
actor.dir = A.dirFromMove(1, 0);            // 向右走 -> 6
actor.setState(1, performance.now());       // 0 站立 / 1 行走
const equip = ['M5MA01', 'M5PA01', 'M5WA01'];                  // 发 / 衣 / 武器 层名

function tick(now) {
  ctx.clearRect(0, 0, cv.width, cv.height);
  A.drawActor(ctx, table, index, pages, actor, equip, 200, 300, now);  // 脚下(200,300)
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);

// 手算一帧（不用 Actor）:
const cp = A.resolveCp(table, 5, 1);                           // 想要走路(CP1) -> 实际读哪个 CP
const fpd = model.cps[cp];                                     // 每方向帧数
const im = A.getFrame(index, 'M50000', cp, /*dir*/4, /*f*/3, fpd);
// im = {page,x,y,w,h,ox,oy}
```
注意：
* 装备层名（如 `M5MA01`）要由你的装备数据给出，装备 id→层名的原版表没追到（见 §8）；调色板换色用 `atlas.json` 的 `variants`。
* `Actor.attack()` 的起点帧重置是自拟（原版置 `obj+0xd4` 的函数没追）；攻击放完 8 帧自动回到站立/行走。
* tick 单位按 ms 推测，网页端用 `performance.now()`。
