## A. 搁置的功能

- **押镖 / 交鏢（C2S 0x41）**——用户 2026-10-20 决定先搁置。
  - 现状：0x41 = `id低16 id高16 耐久 LE32计数 校验字节`（发送函数 0x9cc5c8，调用方 0x6afd6c），k = ((id低16 + 计数) % M) + 1，计数每发一次加 Random(5)+1；服务端 `FUN_008c752d`：没有进行中的押镖就当刷钱（公告 + 随机降一级武功）。
  - 卡在：①押镖怎么开始（事件里 UI 功能号 26 等 + 服务端押镖记录 `押镖.txt` / 内存数组 `DAT_00dd87e4`）；②"到交鏢时间"的判断；③k 落在 2 / 6 以外的提供者要玩家对象 G2+0x210 的 64 位数（计数只能靠随机增量碰 k，不像取鏢能补位）。
  - 下一步：读事件界面功能号 26 / 14（节点「接」act 19）对应的处理块，看它发什么（候选 C2S 0x40 <字节>、0x3E / 0x3F 以外的），再对原版试开始押镖。
- **驛站信件**：原版服务端没有（无邮件表 / 字符串），客户端发包（`37 FF <收件人表> <正文>`、`C7 03 <文字>`）对原版无回应，S2C 0x3F 到达提示只在客户端侧解了。除非新服务端自己做邮件，否则没法验证。
- **鏢局持久化**：原版库里 `biaoju` 表读不了（只有 .frm），託鏢记录只在服务端内存里，重启就没了；`jydata初始.sql` 里有表结构。
