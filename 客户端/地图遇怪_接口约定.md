# 地图遇怪：客户端做了什么、需要服务端定什么

（2026-10-19，网页客户端；配套 `战斗协议_客户端侧.md`）

## 客户端现在的行为

1. **怪物从哪来**：地图数据 `NpcMrg` 里 `model ≥ 50000` 的摆放就是怪物（全部地图共 2647 个，2632 个的型号在 `MOB数据.csv` 里），**型号 = MOB id**。其中 1641 个没有事件，其余有事件（boss / 带对话的怪）。
2. **点怪物**：页面走到它旁边（≤ 400 像素）后发网关 `talk`。
   - 没有事件的怪：直接发 C2S `0x30`，实体 id = `100000000 + MOB id`（实例序号 0）。
   - 有事件的怪 / NPC：先跑对话；对话里的**战斗动作（EvtMrg 动作种类 2）**解析出对手，同样发 `0x30`。
3. **战斗动作的格式**（`evtengine.fight_mobs`）：`l26` 每条 26 字节 = `mob id(u16) + Pascal 名字(21 字节 Big5) + u16(含义未解) + 数量(u8)`；`l26` 为空时 `v[0]` 是 MOB id。一场战斗可以有**多种对手、每种多只**（例如 `邪教教主 ×3`）。
4. 战斗中这只怪在地图上隐藏；**打赢隐藏 60 秒**（客户端自拟的刷新间隔），打输 / 中途退出恢复显示。

## 需要服务端定的

| 问题 | 现状 | 建议 |
|---|---|---|
| **打输之后**：死亡惩罚、气血恢复、回哪里 | 气血停在 0，客户端只能拦住不让再开战 | 先定一个最小规则（例如回城 + 气血恢复到 1），再去原版实测对照 |
| **一次遭遇几只怪 / 几种怪** | 服务端固定 1 只；客户端取事件里第一种对手，数量忽略 | 事件战斗的数量 `n` 可以直接用来生成多只（`D5` 已支持多只，网页 UI 也支持） |
| **谁能打哪些怪** | 服务端只认实体 id，不校验 | 刷新点是客户端数据；要不要读一份做校验（地图 + 位置 + 型号）由服务端定 |
| **怪死后的刷新** | 无状态，客户端自己隐藏 60 秒 | 如果要多人共享，服务端得记"这只怪 N 秒后刷新" |
| **战斗胜负对事件的影响** | 事件战斗动作里 `v[1]`（节点号）疑似是胜 / 败后的转向，没解 | 暂不处理，战斗后对话结束 |

## 已验证

`test_gateway_world_fight.py`（对真 jyserver，隔离库）：点没有事件的刷新点 → 自动开战，对手 = 刷新点型号；战斗中再点同一只被拒。`test_evt.py`：事件里的战斗动作解析出对手。

## 2026-10-19 晚：服务端已定的，客户端已跟进

- **打输**：气血 ≤ 1 算死亡，服务端回「你已死亡」+ `81 02` + `7B 18`（气血记 1）+ `82` + `E6` + `7B 18`；客户端判败后发 E5，页面显示"你倒下了"，随后气血 = 1，可以再开战（网关只在气血为 0 时拦）。`test_gateway_fight_real.py` 覆盖。
- **多只怪**：`0x30` 填充字节第一个 = 同种怪数量 1–5（原版填零 = 1 只）；网关 `fight_start` 带 `n`，事件战斗动作里的数量直接传；实体 id 依次 +1e5，页面本来就支持多只。
- **出招目标**：新服务端按 `D7 [11][12]` 找被打的怪，所以客户端现在把**目标格**放进 [11][12]（原版里这里是施术者自己的格，玩家的目标格在被混淆的 [13][14]）——选哪只打哪只；要发原版形态的传 `cell=自己的格`。
- 刷新点校验 / 怪死后刷新 / 事件胜负分支：服务端不做，客户端自己管（现状：隐藏 60 秒，战斗后对话结束）。
