# 全服心跳、周期换密钥、私聊、定时存档

方法：对原版挂机 4 分钟记录收到的帧和时间（`tools/multi_probe.py` 的 `Client` 会自动跟着换密钥）；新服务端对应实现
`GameServer.on_tick / on_whisper / save_all`，`tests/test_server.py` 有用例；私聊在原版和新服务端上各发 3 个包，回包相同。

## 全服心跳（约每 75.6 秒）

原版有一个全服共用的心跳，每次心跳对**每个在线玩家**：

1. `renwu.online_time += 10`（下线才落库；实测挂 3 次心跳后 MySQL 里 130 → 160）。
2. 发 `0x33`（长帧）= `心跳计数 LE32` + `在线时间 LE32`（心跳后的新值）。
3. 发 `0x99`（短帧）= `04` + 4 字节种子，**随后双方密钥都换成 `derive_key(种子)`**。`0x33` 和 `0x99` 本身还用旧密钥发；
   此后 S2C 帧用新密钥（实测种子 `29 62 3e b6` → 密钥 0x52，之后的帧头密钥确实是 0x52），C2S 帧的密钥基数也变成新值
   （`新基数 XOR 序号`；不跟的话原版静默忽略之后所有指令——早先"偶发丢指令"的真正原因）。

种子在原版内置的 10 个里随机挑：`0e ae a5 31…38`、`29 62 3e b6`、`21 3d b0 96`。

心跳计数就是登录包 `0x1E` 开头那个 4 字节计数器（同一个数，下一次心跳 +1）。实测起点是连着前几天的，挂钟时间决定，
大约 `321 + 当天秒数 / 75.6`；新服务端从 1 开始数，客户端是否在意绝对值未知。心跳周期实测 74.6–76.7 秒，取 75.6，
服务端 `--tick` 可调，`0` 关闭（关闭后不再发这对帧，密钥永远是 0x7D，客户端大概不会有问题，但与原版行为不同）。

## 私聊 C2S 0x03

载荷 = 目标 jyid(LE32) + 文本字节（原样转发）。目标在线就收到 S2C `0x04`（长帧）= `03` + 发送者 jyid(LE32) + 文本；
目标不在线什么也不回（发送者也收不到提示）；不扣饮食饮水。

没做：`0x04` 的"轻频"（组织聊天后来做了，组织只在内存里，见 `docs/组织.md`）
（载荷 `N + N×4 字节 + 文本`，发给某个名单，我试了发给在线的人也没人收到，名单来源应该是队伍 / 好友状态，没查）。

## 定时存档

原版只在下线时把角色存回库，进程崩溃就丢进度（试探时原版崩过）。新服务端额外每 60 秒（`--autosave`，`0` 关闭）
把所有在线玩家存一次；正常退出（Ctrl+C）时也会存。
