# 药品效果（C2S 0x0B 的后半部分）

前半部分（找物品、扣数量、精气神内/饮食饮水/学点/六属性/名声/实战/历练、`0x7B` 顺序）见 `docs/装备与物品.md`。
这里记 2026-10 补测的其余列。方法：`tools/effects_probe.py` —— 新建一个全新角色（走新建角色流程），
往它的 `item` 表插药，**重启原版服务端**（背包只在启动时读进内存），逐个使用，下线后读库对比；
最后用 20 种药在原版和新服务端上各跑一遍，输出逐行相同（`tests/test_items.py` 里有逐条用例）。

## 已实现（与原版一致）

| 药品列 | 原版行为 |
|---|---|
| 永久攻 / 永久防 | 累加进 `renwu.wuqiqiangdu` / `fangjuqiangdu`（**下线才落库**）；只回 `0x0B` 确认，**没有 0x7B**。登录包里的武器 / 防具强度 = 装备攻防之和 **+ 这两列**（实测：吃了霹雳丹 +50、金钟丹 +100、没装备的号登录时是 50 / 100）。所以以前「库里这两列恒为 0」只是因为测试号没吃过药 |
| max气 | `zuidaxue += 值`；顺序是**先** `0x0B` 确认，**后** `0x7B 17 01 <新最大气血 LE32>`（和普通药相反）；下线落库 |
| 攻击 / 防御（临时） | 只回 `0x0B` 确认，没有任何 0x7B，库不变（临时增益只在内存里） |
| 毒、酒醉、内伤、麻痹、情花毒、赤练毒、走火入魔、流血…（状态列） | **不产生任何包**，也不改库；药里的精气神内效果照常生效。状态只存在服务端内存，没有 0x7B，也没有战斗逻辑用它，所以新服务端不记录 |

## 原版静默不处理的情况（不回包、不扣数量）

- 带 **max精 / max神 / max内** 的药（立春补精丹 31171、立春提神丹 31219、千年灵蛇丹 28053、雪地肥蜈蚣 58304、生日祝福丹 28276…）。
  把对应上限调低到 100 再试也一样——不是「超过上限」，是这几种就没实现。**max气 是实现了的。**
- **只含状态列**的药，例如刀伤药 29001（只有「流血 −20」）。推断：没有任何可见效果就不处理（只有这一个样本，其他
  纯状态列的药在药品表里根本不存在）。
- **药品表里没有效果列**、又不是下面的特殊药：金娃娃鱼 28197、新药1 28222…

## 特殊药（药品表里没有效果列，原版有专门逻辑）

先回 `0x0B` 确认，数量 −1，再追加：

| 物品 | 追加 | 文本（`0x1A`，子类型 `64` + BIG5） |
|---|---|---|
| 28170 内力不减丹 | `0x1A` | 內力不減丹效果開始，下線失效﹗ |
| 28172 三黄宝腊丹 | 无 | — |
| 28255 神行丹 | `0x99`(短) = `05` + jyid(LE32) + `ff`，再 `0x1A` | 神行丹效果開始，下線失效﹗ |
| 28388 巅峰自修加倍水（不在药品表） | `0x1A` | 巔峰自修加倍水效果開始，重登失效﹗ |

「下線失效 / 重登失效」说明这些是内存里的临时增益；新服务端只回包，不实现增益本身。

## 顺带发现：服务端会周期性换密钥，客户端必须跟

登录后每隔几十秒，原版会发 `0x33`(长帧，8 字节) + `0x99`(短帧) `04 <4 字节种子>`。收到后，**此后 C2S 帧的密钥基数
变成 `derive_key(种子)`**（实测种子 `0e ae a5 31` / `…33` / `…36`，跟着换之后指令立刻恢复响应；不跟则被静默忽略——
我之前把这个当成「偶发丢包」，其实是模拟客户端没跟着换密钥）。`tools/multi_probe.py` 的 `Client.drain` 现在会自动跟。
新服务端还不会发这对帧（客户端不会因此出问题，只是密钥永远不变）。
