# 事件引擎：C2S 0x6B

方法：`rea` 在 `服务端.exe` 里按字符串线索（「此事件暂未开放」「刷事件」「请增加地图事件」「事件错误.txt」）反查引用，
全部落在 `0x63be2f`（108 KB、18 段的巨型函数，C2S 分发表里早就有 `6B → 0x63be2f` 这一条，之前没人验证）；
再用 `tools/event_probe.py` 对本机原版（127.0.0.1:6731）发包、读 MySQL 对照。新实现 `jyserver/events.py`，
`tests/test_events.py` 把**同一份 110 步脚本**（`tests/fixtures/events/scenario_a.steps`）喂给纯函数，逐包、逐库对原版的录像
（`scenario_a.orig.json`）；另外开新服务端、用同一个脚本走真实网络再比一遍，见文末「对照结果」。

证据等级：**实测** = 原版回包/库里亲眼见到；**反编译** = 读代码；**推断** = 没数据能触发，按代码/字符串猜的。

## 请求

C2S 0x6B 载荷至少 8 字节：`[4 字节 X] [地图 LE16] [事件id LE16]`。（**实测**；客户端实际会在 X 里放什么没抓到过，原版不看它，只在 type≥3 时把它原样回显。）

原版把解密后的整帧文本（`F4 44 <长度> 6B <载荷…>`）按空格拆成十六进制 token，总 token 数 = 帧长度字节（短帧里 = 4 + 载荷长度），
< 12（载荷 < 8 字节）就什么都不做。**反编译**

1. 地图（`payload[4:6]`）必须等于玩家当前地图，否则是「刷事件」：先回 `7D 事件id`，再给**全服**发 `0x14` 子类型 `0e`
   「玩家:<jyid>，姓名:<名字>刷事件，武功隨机掉一級」，并写 `jilu\事件错误.txt`。**实测**。
   原版还会让这个玩家随机掉一级武功（`0x546e15`）——实测 `kf` 表里没看到变化，**没实现**。
2. (事件id, 地图) 属于一小撮写死的专门事件（战役、杀龟大会：`191/7000 550/5000 457/9351 5/9351 350/4000 863/5000 3/3501 5/10852 252/1000 427/2000 150/3000 137/5000 866/5000`），
   不走 事件.csv。**反编译**（常量已读出）；新服务端只记日志、不回包，**没实现**。
3. 在 事件.csv 里找 (地图, 事件id)，重复的取**第一条**（线性扫描；CSV 里有 84 组重复）。找不到：回 `7D 事件id + 地图`（「请增加地图事件」，只写日志）。**实测**。
4. 「开关」列不是 `1`：`0x1A`「此事件暂未開放」+ `7D 事件id`。**推断**（`事件.csv` 的开关列全是 1，触发不了；文字取自 exe）。
5. 执行「结果」列（见下）。执行完回 `7D 事件id + 回显`。

### 回包 `S2C 0x7D`（长帧）

`事件id(LE16)` + **回显**。回显由事件的 `type` 列 N 决定（**实测** type 0–5、**反编译** 其余）：把整帧 token 序列
`F4 44 <长度> 6B <载荷…>` 从尾部往前数，k=1..N，每次取 `token[n-2k-2], token[n-2k-1]` 两个字节，越靠前的越先。于是
N=0：无；N=1：地图；N=2：`payload[2:4]` + 地图；N=3：`payload[0:2] payload[2:4]` + 地图；N=4：再往前是 `<长度> 6B`；N=5：再往前是 `F4 44`。
**不够取（n < 2k+1）时原版什么都不回**——N≥6 的事件（61 条）用 8 字节载荷请求永远没有回应（但结果语句已经执行过了）；载荷更长时，"尾部"指的是实际的帧尾，不是地图。
type 为空（找不到事件）按 N=1。

## 结果语句

按 `;` 拆语句（空串跳过），再按 `:` 拆字段。**字段不足 3 个 → 记日志、放弃整个事件，什么都不回**（`金钱:10`、`物品:58197-10` 这类 CSV 手误就是这样，**实测**）；
**多于 3 个 → 这条语句被跳过**（`物品:40259:-1:物品:28142:3` 什么都没发生，**实测**）；第一个字段不认识 → 跳过（`输:金钱:-500`，**实测**）。
数字按易语言「到整数」解析：取开头的整数，取不到（`-`、空）就是 0。**已执行的语句不回滚**；失败就停，后面的不执行。

| 语句 | 行为 |
|---|---|
| `标记:ID:N` | N>0：加 N 次；每次 `0x77`（得到，载荷 `ID(LE32) (0x100+类型)(LE16)`）+ `0x14 08`「得到標記﹕<名字>」。类型 = `标记.csv` 第 3 列（不在表里的 ID：类型 0、名字空、**不入库**）。库：`biaoji(jyid, biaoji, zhuangtai)` 每次加一行，`zhuangtai` = 类型。N<0：每次先发 `0x6B`（同载荷，**缺不缺都先发**），有则删一行 + `0x14 08`「失去標記﹕名字」；没有 → `7D 事件id`、`0x14 08`「缺少標記﹕<ID 数字>」，中止。 |
| `标记2:ID:N` | 同上，但没有这个标记**不算错**，照样报「失去標記﹕名字」，继续。 |
| `物品:ID:N` | N>0：`0x77` + `0x14 08`「得到物品﹕<名字>」×N，背包 `state=200` 那行 `shuliang += N`（没有则新增）。类型字节 = 耐久（`装备数据.csv`/`药品.csv`），不在表里 200。N<0：每次 `0x6B`，有则减 1（减到 0 删行）+「失去物品﹕名字」；没有 → `0x1A`「物品不足」、`7D`、`0x14 08`「缺少物品﹕名字」，中止。物品 ID 不在物品表里也照样入库。 |
| `物品2:ID:N` | N<0 时没有物品不算错：`0x6B`、`0x1A`「背包沒有此物品」、`0x14 08`「失去物品﹕<ID 数字>」，继续；有则「失去物品﹕<ID 数字>」（注意：2 版本显示 ID，不显示名字）。 |
| `属:金钱:N` | `jy_money += N`，`0x7B 3c` + `0x14 08`「金錢改變﹗」。**N<0 且 钱+N ≤ 0：整个事件中止，什么都不回**（花光也不行，**实测** 100000 − 100000 不行、100001 − 100000 行）。 |
| `属:金钱/名声/历练/实战/善恶/杀气/PK值/学点:N` | 加 N 后按各自的上下限夹取（**实测**，见下「数值夹取」），`0x7B <子类型>` + `0x14 08`「…改變﹗」。子类型：名声 `3d`、历练 `44`、实战 `2b`、善恶 `45`（值 = 库里 `evil_val − 2000`）、杀气 `37`、PK值 `38`、学点 `28`（文字「學點改變﹗」）。 |
| `属:门技:N` | 见下「门技」。**实测** |
| `基本:<名>:N` | 见下「基本」。**实测** |
| `武功熟练度:ID:N` | 见下「武功熟练度」。**实测** |
| `熟练:…` `技能:…` `反向:…` `属:裁缝/伐木/饮水/饱食…` | **什么都不做**（实测：即使有对应武功 / 技能等级 / 饮水值也一样），只有事件末尾的 `7D`。 |
| `属:门派:N` / `属:师承:N` | 直接赋值 `school` / `master`，**短帧** `0x7B 41`/`0x7B 42` + LE32，没有 0x14。**实测**。 |
| `验证:标记:ID` | 身上**有**这个标记就失败（`验证` = 一次性检查，防重复领奖）：`0x1A`「身上有標記﹕ID,無法接此任務﹗」+ `7D 事件id`。**实测** |
| `验证:实战:V` | `combat_exp < V` 失败：`0x1A`「實戰不足，需V,無法接此任務﹗」+ `7D`。**实测** |

| `验证:物品:ID` | 身上有物品就失败；文字「身上有物品﹕<ID>,無法接此任務﹗」**推断**（没有物品能触发）。 |

## 数值夹取（`属:…:N`，实测；之前文档里的 [0,4e9] 是错的）

加减 N 之后：**N>0 只卡上限，N<0 只卡下限，N=0 不动**（所以超过上限的旧值 −1 不会被拉回上限，低于下限的善恶 +1 也不会被拉回；`jy_money`=1.5e9 时 −1 → 1499999999）。

| 属性 | 上限 | 下限 |
|---|---|---|
| 金钱 | 1,000,000,000 | N<0 且 钱+N ≤ 0 → 整个事件中止（上面已写） |
| 名声 / 历练 / 杀气 | 1,000,000 | 0 |
| 学点 | 65200 | 0 |
| 善恶（库里 `evil_val`，显示值 = evil_val − 2000） | evil_val 3000 | evil_val 1000 |
| **PK值** | **100**（不是 200） | 0；**不分方向**都夹到 [0,100]（500 −1 → 100，N=0 也夹成 100） |
| 实战 | 无；N>0 时结果按 2^32 回绕（4294967295 +1 → 0），N<0 夹 0 | 0 |

实战的值超过 2^31 后，原版还会把低 11 位左右丢掉（2000001005 + 2e9 → 4000000000），原因没查，**没实现**；事件.csv 里实战最大是 5，碰不到。

## 门技（`属:门技:N`，原版 `0x6a49fb`）

1. `T = (school_skill_exp + N) × 10000`，转成 **32 位有符号整数，超范围按 2^32 回绕**（N=300000 → T 回绕成负；N=429497 → 2704）。N 到 2e9 以上，原版会先把乘积转成科学计数法字符串再解析，结果乱七八糟，没实现（事件.csv 里 |N| ≤ 500000）。
2. `T < 1`：发 `0x7B 49`=原等级、`0x7B 4a`=0，库里 `school_skill_exp` 置 0（等级不变）。（等级已经是 100 也发。）
3. 否则，等级 `L < 100`：`while T > (L+1)²: L += 1; T −= L²`；`L > 100` → 等级 100、经验 0；否则等级 L、经验 T（剩下的）。发 `0x7B 49`=等级、`0x7B 4a`=经验（LE32），写库。
4. 否则（等级 ≥ 100）：什么都不改、不发 `0x7B`。
5. 三种情况都发 `0x14 08`「增加門技」，和有没有入门派无关。存下来的经验是「剩余 T」，下次又 `(exp+N)×10000`（原版的毛病，照抄）。

实测点：0 级 +1 → 30 级、经验 545；+33 → 99 级、1650；+34 → 100 级、1650；5 级经验 20 −1 → 82 级、2890。

## 基本（`基本:<名>:N`，原版 `0x63be2f` 里）

**只发一个 `0x68` 长帧，什么都不写**（`renwu` 的等级 / 经验列不变，下一条语句还是从库里的原值算起，不累加）。

- 名字 → 武功 ID：基本刀法 8001、枪法 8002、剑法 8003、鞭法 8004、棍法 8005、内功 8006、刺术 8007、身法 8008、毒术 8009、医术 8010、阵法 8011、搏击格斗 8012、闪躲纵跃 8013、基本暗器 8014、拆招卸力 8015、读书识字 8017；对应 `renwu` 列 `daofa qiangfa jianfa bianfa gunfa neigong cishu shenfa dushu yishu zhenfa boji shanduo anqi chaizhao dushushizi`（等级）和 `<列>exp`（经验）。**交易之道**（8016，`jiaoyi`）原版什么都不做。**枪法的经验原版读成 0**（库里 `qiangfaexp` 登录后丢，下线写回 0），新实现照此算但不改库。名字不认识 → 什么都不做。
- 算法：`total = exp + N`；若 `total` 在 32 位有符号范围内：`while total > cost(L+1): total −= cost(L+1); L += 1`，`cost(k) = floor(系数 × k³)`，系数 = 1（读书识字 1.5）；**没有等级上限**（99 级照样升，0 级 +2e9 → 298 级）；N=0 也会把已经攒够的经验升上去；N<0 经验直接变负（不升不降）。超出 32 位有符号范围：不升级，帧里放低 32 位（+3e9 → `00 5e d0 b2`）。
- 帧 `0x68`（长帧）：`武功ID(LE16) 等级(LE16) 经验(LE32) 学点(LE16) 当前精(LE16)`（和学武功那条同一格式，只是经验不为 0）。

## 武功熟练度（`武功熟练度:ID:N`）

- N=0：什么都不发。ID 不在武功列表里（含 0、负数、不存在的）：`0x1A`「無此武功」（短帧）。
- 在列表里（等级 0 的删除残留也算）：`kf_exp += N`（**不升级**，等级不变，32 位回绕，可以变负），发 `0x70`（长帧）= `学点(LE16) 当前精(LE16) 武功ID(LE16) 等级(LE16) 新经验(LE32)`。
- `熟练:<名>:N` 实测什么都不做；`技能:<名>:N`（猎人 / 裁缝 …）、`属:裁缝/伐木/饮水/饱食` 同样什么都不做（原版的 `0x76 BE <技能号>` 帧在别处用）。

## 对照结果（经验类语句，2026-10-19）

`tools/exp_compare.py` 的 85 个场景（门技、各属性上下限、实战回绕、基本 ×17 名、武功熟练度、熟练 / 技能 / 属:裁缝…）对原版和新服务端各跑一遍，比较 8617293 收到的帧和下线后的库：
**除下面 4 类已知差异外逐行一致**。已知差异（都是极端数值或原版存档上的毛病）：
- 实战超过 2^31 后原版丢低位（cap-实战 / cy1）、库里存成有符号数或保持旧值（cx4 / cx5）；
- 门技 N ≥ 2e9（原版转成科学计数法字符串，sk-ovf2147483647 / sk-ovf99999999999 / sk-ovfn99999999999）；
- 枪法经验：原版登录时读成 0、下线写回 0（库里 `qiangfaexp` 被清掉）；新实现帧里同样按 0 算，但不改库（bm-map / qx 的「basic:」行）。
`tests/test_events_exp.py` 把上面的实测值固化成 26 个单元测试。

## 没做 / 未解

- `属性:` 前缀、`输:`、`金钱:10` 这类 CSV 手误：同前，跳过 / 放弃整个事件（上面「字段不足 / 多于 3 个」）。
- 武功：已做（上表）。门派编号直接来自「防挂验证.csv」的「门派」列（和 武学系数.csv 的门派名无关）。
- 实战 > 2^31 时原版丢低位的怪行为、门技 N ≥ 2e9 的科学计数法行为：没实现（见上）。
- **限时标记**：类型不是 200 的标记（12、24、199…）的 `zhuangtai` 会随时间倒数（实测 `51392`: 199 → 198，发生在某次下线落库时），到 0 会不会删、几分钟一格，没摸清。新实现不倒数。
- 「刷事件」的惩罚（掉一级武功）、`事件错误.txt` / `事件得钱.txt` / `事件得物品.txt` / `事件得武功.txt` 这几个日志文件没写（只写 Python 日志）。
- 类型 N ≥ 6 的事件需要客户端发更长的载荷才有回应；真实客户端的 0x6B 载荷前 4 字节装什么、更长的载荷长什么样，没抓到过。
- 原版事件里「NPC 点击/对话」的界面部分（弹对话框、选项）完全在客户端；服务端只在玩家点了选项之后收到 0x6B。NPC 本身的摆放（地图上哪里有哪个 NPC）还没碰。
- `NPCID` 列在 事件.csv 里全是空的。


## 学武功（事件语句 武功:ID:N）

事件里的 `武功:ID:N` 走原版 `0x6a520b`（学）/ 同一个分支里的忘；条件检查在 `0x6a64bf`，读的是内存里的「防挂验证.csv」表（`DAT_00dd87f4`）。

- 条件列：`武学条件1/2/3 + 等级`（前置武功必须在列表里且等级不低于；删除残留的等级 0 不算）、`臂力 胆识 悟性 福源 定力 机敏 根骨`（人物表 `str crg wint luk dex agi vit`）、`名声`（`fame_val`）、`历练`（`exp_val`）、`实战`（`combat_exp`，64 位比较）、`上线时间`（`online_time / 48` 小时）、`门派`（`school` 必须相等）。
- `0x68` 帧的最后两个 LE16 是人物表的 `study_count`（学点）和 `dangqianjing`（当前精）。
- 武功名在公告里用 `武学系数.csv` 第 5 列简体名过 `to_big5`。核对这一步时发现原版的简繁转换规则和旧实现不同，已改（见下）。
- 实现 `jyserver/kungfu.py: learn / forget / meets`，由 `events.py` 的 `武功` 语句调用；事件中途的全服公告用 `Result.inline`（位置 = 当时 `to_self` 已有几帧）穿插在自己的帧之间，保证 `公告 → 7D` 的顺序。

## 简繁转换（to_big5）更正

用 `tools/name_map_probe.py` 向原版问了 846 个武功名（3521 个字）的真实 BIG5 字节（存在 `data/orig_name_bytes.json`），规则是：**先看这个字能不能直接编成 CP950**（能就原样，所以 万 体 气 极 网 儿 蚕 恒 都不转繁体），不能的再过 S2T（NLS 简繁表）再编 CP950，还不行变全角空格 `a1 40`（噼 勐），全角句点 `．`(U+FF0E) 是 `a1 4f`。旧实现是先 S2T 再编码，对 万 体 气 等多转了一次。`tests/test_state.py` 用这 846 个名字做回归。

## 登录包里的标记（顺带发现）

`0x1E` 开头的「背包记录」（5 字节一条：物品ID LE32 + 耐久字节）后面，除了一条 `(0,0)`，还跟着该角色 `biaoji` 表里每个**标记ID>0**的行（标记ID LE32 + `zhuangtai` 低字节），按行顺序；
建号时插的那条 `(0,0)` 标记行不产生记录。**实测**：给号加 3 个标记，包里多 15 字节，位置在 `(0,0)` 之后。`jyserver/state.py:inventory_records` 已按此生成，
`jyserver/creation.py` 建号时补一条 `(0,0)` 标记行，`jyserver/importer.py` 现在也导入 `biaoji`。

另：物品不在 `装备数据.csv` / `药品.csv` 里时（事件可以给表外的物品，如 33757），背包记录和 `0x77` 帧里的类型字节是 200（`ItemTable.of` 的默认值由 0 改为 200）。
