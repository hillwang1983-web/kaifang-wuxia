# 武功：0x61 装备 / 0x6A 删除

方法：反编译 `0x6b3cad`（61，约 1600 行，十几个槽位分支，每个分支都是同一套检查）和 `0x8904a3`（6A），再用 `kf` 表里放了几条武功的 8617293 号对原版逐条验证
（`tools/multi_raw.py`、`tools/kf_matrix.py`、`tools/kf_compare.py`）。新服务端 `jyserver/kungfu.py`；`tests/test_kungfu.py` 期望值来自原版回包；
`tools/kf_compare.py` 的 11 套场景对原版和新服务端各跑一遍，回包（A 和旁观号 W）与下线后的 `kf` 表逐项一致。

## 原版的数据

玩家的「拥有的武功」是内存里的一个列表（登录时从 `kf` 表读，`player+0x170`），等级、经验各一个并行数组（`+0x174` / `+0x178`）。
**装备**的状态在内存里别处，服务端只回显、之后没有任何地方看得到它（可能战斗用，战斗没做）；所以新服务端不存装备状态。

## C2S 0x61 装备武功

载荷 = 槽位(1) + 武功 ID(LE16)，至少 3 字节，后面多的不看。

| 情况 | 回包 |
|---|---|
| ID = 0 | 自己收 S2C 0x6E = 载荷前 3 字节原样（**不管槽位、不查拥有**；槽位 15、255 也回） |
| 自己没有这门武功（不在列表里） | **全服**收 S2C 0x14（长帧）= `0e` + <自己的名字> + 「嘗試刷武功﹗」 + 武功名（武学系数.csv 里有这个 ID 才带，取第 5 列简体名转繁体；ID 不在表里就不带）。不管槽位 |
| 有，槽位 0–14 | 自己收 S2C 0x6E = 槽位 + ID（回显）。**没有类型 / 门派 / 槽位种类检查**：心法能放进任何槽位，别门派的武功、转生武功 3860、表里没有的 ID（只要拥有）都收 |
| 有，槽位 > 14 | 静默 |
| 载荷不足 3 字节 | 静默 |

「有」包括被删除后残留在列表里的（等级 0），见下。

## C2S 0x6A 删除武功

载荷 = 1 字节（不看）+ 密码长度 N(1) + 密码 N 字节 + 1 字节（标记，不看）+ K×武功 ID(LE16)，至少 4 字节。密码是**账号密码**（`account.password`，不是 0x98 的二级密码，也不要求先验证）。

原版数的是 token 数：m = 载荷长 − N − 2，条目数 K = CInt((m − 1) / 2)（VB 的 CInt 是四舍六入五成双）；K ≤ 0 整条静默。条目 i 占密码后第 2+2(i−1) 起的 2 字节（LE16）。
m 是 4 的倍数时最后一条会越出载荷：不报错，那个 ID 谁也匹配不上。顺序：

1. 解析条目，**遇到 3860（转生武功）** → 自己收 0x1A「轉生武功無法刪除﹗」，结束（先于密码检查；前面已解析的也不删）；
2. 核对密码：不对（含长度 0）→ 0x1A「密碼錯誤」，结束；
3. 按条目顺序处理：在列表里找第一个相同的 ID，找到 → **只把等级、经验写成 0**，自己收 S2C 0x7A = `02` + ID(LE16)；没有的 ID 跳过。

## 存档

下线（以及定时存档）写 `kf` 表时，**等级为 0 的行不写**（经验是不是 0 无所谓；`kf_lvl` 7 / `kf_exp` 0 的行保留），所以删除要到下次登录才生效。新服务端的 `kungfu.persistable` 在写库时滤掉，内存里的行不动。

## 没做 / 不确定

- 装备状态本身（哪个槽位放了哪门武功）没存，也没验证它是否影响别处；`0x61` 反编译里每个槽位分支还有若干「程序命令标记」调试串和日志，没碰。
- 原版在数据库连接取不到时回「暫無空閒」，新服务端没有这个失败路径。
- 条目越界时原版读到的"空" token 具体是什么没追，只确认了不会匹配上拥有的 ID，也不会触发 3860 检查。
- 事件语句里的「武功:ID:等级」（学 / 忘武功）见 `docs/事件引擎.md`「学武功」，同样在 `kungfu.py`，`kf_compare.py` 的 `learn-*` 场景（9 套）与原版一致。
