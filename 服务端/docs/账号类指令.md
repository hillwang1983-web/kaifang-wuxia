# 账号类指令：改外号(0x13)、删除角色(0x33)、二级密码(0x98)

方法：反编译 `0x8bfbf4`（0x13）、`0x8cb1be`（0x33）、`0x8c6681`（0x98），再用 `tools/cmd_probe.py` / `tools/delete_probe.py` 对原版逐条试；
删除用一次性克隆号（`tools/layout_probe.py clone/cleanup`）。新服务端 `jyserver/account.py`，`tests/test_account.py` 和 `test_server.py` 里的用例期望值来自原版回包；
改外号 / 二级密码另用 `tools/cmd_compare.py`（`nick` `nick-kf` `password` 三套场景）对原版和新服务端各跑一遍，回包与下线后的库状态逐项一致。

## 改外号 C2S 0x13

载荷 = 新外号的**原始字节**（客户端发的 BIG5），到第一个 `00` 为止；空载荷 / `00` = 清空外号；没有长度上限（试过 36 字节）。只有进入世界后有效。

- 库里 `renwu.nickname` 存**简体**：BIG5 解码后繁转简（`c4 e3 ba c3` → `斓疑`）。新服务端用 `state.from_big5`（`S2T` 表的反向）。
- 自己收 S2C `0x15` = jyid(LE32) + `V7Z<n>-` + 外号原始字节。
- **全服**（含自己）收 `0x14` 长帧子类型 `0e` = 名字（BIG5）+ `更改了外號﹕`(`a7 f3 a7 ef a4 46 a5 7e b8 b9 a1 52`) + 同一段 `V7Z<n>-外号`。
- 前缀 `V7Z<n>-`：`7` 是 VIP 等级（恒为 7）；`n` = 角色的 `kf` 表里 `kf_id = 3860`（转生武功）那条的 `kf_lvl // 10`，没有就是 0。实测 `kf_lvl 25 → Z2`。
- 这个前缀就是别人看到的称号（`state.TITLE_PREFIX = V7Z0-` 登录时用的是 Z0 版）；改了外号之后原版的内存称号带新的 `n`，这里登录 / 出现包仍用库里 `nickname` 加 `V7Z0-`，没有区分 Z 数。

## 删除角色 C2S 0x33

载荷 = 1 字节（不看）+ 密码长度 `n`(1) + 密码 `n` 字节，后面多的字节不看。**只能在选角色界面（还没发 0x19 进入世界）用**：进入世界后发它，原版**会崩**（试了一次，
服务端.exe 进程还在但 6731 不监听了，要重启），所以新服务端对已进入的连接不理会。

| 情况 | 回包 / 效果 |
|---|---|
| 密码 = 账号密码 | 删除 `renwu` `char_equip` `jineng` `kf` `item` `biaoji` `qianzhuang`（原版还会删 `biaoju` `ypsx` `zssj`，这几张表这份库里不存在，语句静默失败）里这个 jyid 的行，**账号行保留**；回 S2C `0x36` `01`。连接不断，再发一次同样的包还是回 `0x36 01`（语句删不到行也回）。之后这个账号走「没有角色」的流程，可以重新建角色 |
| 密码不对（含 `n = 0`） | `0x1A` `64` +「密碼錯誤」（`b1 4b bd 58 bf f9 bb 7e`） |
| 载荷不够长（`n` 比后面的字节多） | 静默 |
| 载荷只有 1 字节、`n` 缺失 | **原版崩**（两次）；新服务端静默 |

原版还会把这个玩家从内存里的在线 / 列表数组里摘掉，这里没有这些数组。

## 二级密码等 C2S 0x98

首字节是子指令：

| 子指令 | 载荷 | 回包 |
|---|---|---|
| `0D` | `0D` 长度 `n` 密码 `n` 字节 | 对 → S2C `0xB8` `10`（原版同时置 `玩家+0x14c = 1`「已验证」，新服务端在连接上记 `verified`，目前没有谁用它）；不对（含 `n = 0`）→ `0x1A`「密碼錯誤」；载荷不够长 → 静默 |
| `0F` | 至少 6 字节 | S2C `0xB8` `13` + 载荷第 2–6 字节（回显 5 字节）；不足 6 字节静默 |
| `0E` | 至少 6 字节 | S2C `0xB8` `12` + 同样 5 字节 |
| 其他 | | 静默 |

`0F` / `0E` 的用途（客户端的二级密码界面？）不清楚，只做了回显。**原版对某些过短的载荷会崩**（`0D` 只有首字节、`0E` 不足 6 字节等其中之一，没逐个分清），新服务端一律静默。

## 没做 / 没弄清

- 删除角色时对 `biaoju` 等不存在的表无事可做；原版摘内存数组的动作没有对应物。
- `0xB8` 帧里 `10` 之后客户端怎么用、`0x14c` 标志被谁检查（`0x6A` 删除武功要的是账号密码、不检查这个标志，见 `docs/武功装备与删除.md`）没查它被谁检查。
- 改外号时原版内存里的称号 `V7Z<n>-外号` 会影响之后别人看到的名字牌；新服务端没有这层内存称号。
