# 杂项指令初步探测（2026-10-19）+ 健壮性测试

## 健壮性：随机包灌新服务端

`tools/fuzz_server.py`：进程内起一个服务端（内存库、三个夹具号进入世界），三个模拟客户端轮流发随机 opcode（60% 取已有处理函数）+ 随机载荷（0–40 字节，夹杂合法 jyid / 物品 ID / 武功 ID），`dispatch` 被包了一层记录异常。
`--risky` 模式每包开一个新连接，专发 `01 / 19 / 20 / 33 / 13 / 76 / 98`（登录、进入、建号、删号、改外号、摇点、二级密码），含只握手不进世界的情况。

结果：5 个种子 × 约 5500 包 + 3 个种子 × 2761 包的普通模式，以及 2 个种子 × 150 连接的 risky 模式，**没有任何处理函数抛异常**，三个号一直在线。这说明所有已实现的处理函数对长度不对 / 乱填的载荷都是静默或断开处理，不会把服务端带崩（原版倒是有好几处会崩，见各文档）。

## 对原版发空载荷 / 零载荷 / jyid 载荷看到的回应（没实现）

| opcode | 原版回应 | 备注 |
|---|---|---|
| `24`、`07`、`62`、`9F`、`31` | 无 | `9F` 是反编译里的「未启用此功能」空壳 |
| `91` | `0x1A`「物品不足」+「重登后變更」 | 某个要物品的「变更」类功能，条件不满足的路径 |
| `66` | `0x75 06` | 不管载荷；含义没追 |
| `1B` | 一串 `0x7B 1a 01 <值>` + `0x1A` 文字（含「…00 00 …」之类拼出来的提示） | 看起来是循环在列表上；没追 |
| `67` | `0x1A`「請從外挂上判門﹗」 | 拒绝路径 |
| `60` | `0x1A`「物品不足」+ `0x05 <自己jyid> 01`（自己下线帧） | 疑似拜师 / 转门派类，失败路径之后还把自己踢出世界 |
| `5E` | `0x14 08`「已達到消點最大等級」 | 消点（学点）功能的上限路径 |
| `40` | `0x4D 04 88 13 00 00` | 镖局组，见 `镖局-初步探测.md` |

这些都只是「条件不满足」的那条路径，成功路径需要有对应物品 / 状态才能触发，没有真客户端的流量就不知道客户端怎么用，所以没有实现。
