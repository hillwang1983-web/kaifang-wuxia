# 组织（帮派）：0x45 创立 / 0x4E 招收 / 0x4F 应答与列表 / 0x50 踢人 / 0x51 退出 / 0x56 查询 / 组织聊天

方法：反编译 `0x8cf0eb`（45）、`0x8cfd83`（4E）、`0x8d086a`（4F）、`0x8d2348`（50）、`0x8d1bda`（51）、`0x8ccf03`（56）和 `0x72e01f` 的子类型 05 分支，
再用三个模拟客户端 A=8617293、W=1234567、C=123456 对原版逐条验证（`tools/multi_raw.py`、`tools/org_compare.py`）。
新服务端 `jyserver/org.py`；`tests/test_org.py` 期望值来自原版回包；`tools/org_compare.py` 的 20 套场景（约 400 行回包）对原版和新服务端各跑一遍（每套前两边都重启），逐行一致。

## 原版的数据结构（新服务端照搬）

- 全局**组织数组**（号码 = 下标 + 1，**只增不删**，重启才清）：名字（原始字节）、创立者 jyid、成员 jyid 数组（int，**可重复**）。
  库里 `zuzhi` / `zuzhirenyuan` 两张表只有 .frm、没数据，原版不读不写，组织只存在内存里。
- 每个玩家一个**组织号字符串**（`player+0x450`，缺省 `"0"`），**不随下线清掉**（同一进程里重新登录还在，聊天 / 列表照常），原版重启才没。
- 组织号数值为 0（或越界）时，原版里数组下标出错，这一次指令什么也不做、不回包、不崩——新服务端同样静默。
- **踢人把被踢者的组织号写成 `" 0"`**（带前导空格）：数值上是 0，但字符串和 `"0"` 不相等，所以被踢的人**既不能创立组织（「已有組織﹗」）、也不能被招收（「對方已有組織﹗」）**，只能自己再用 `0x4F 01` 加入某个组织，或自己 `0x51` 退出（那会写成 `"0"`，才恢复正常）。

## 指令

| C2S | 载荷 | 行为 |
|---|---|---|
| 0x45 创立 | 组织名（原始字节，不转码；空载荷不回包） | 自己组织号 ≠ `"0"` → 自己收 0x1A「已有組織﹗」；名字和现有组织完全相同（区分大小写）→ 0x1A「組織名重複」；否则新建（创立者同时是第一个成员），自己的组织号 = 新号码，自己收 S2C 0x4F = 自己 jyid + 组织号(LE16) + 名字，**全服**收 S2C 0x14（长帧）= `0e` + 创立者名字(BIG5) + 「，創立了組織﹕」 + 名字 |
| 0x4E 招收 | 对方 jyid(LE32)，至少 4 字节 | 自己组织号 0/越界 → 静默；自己不是该组织的创立者 → 自己收 0x1A「組織創立者才能招收﹗」（**先于**下面的对方检查）；对方不在线 → 静默；对方组织号 ≠ `"0"`（包括自己、被踢的人）→ 自己收 0x1A「對方已有組織﹗」；否则对方收 S2C 0x54（长帧）= 创立者 jyid(4) + 组织名长度(1) + 组织名 + 1802 字节固定模板（组织号 LE16 在模板第 28 字节处）。对方还要自己发 0x4F 01 才算加入 |
| 0x4F 01 加入 | `01` + 招收人 jyid(LE32)，至少 5 字节 | 招收人在线 → 自己的组织号字符串 := **招收人的**（不检查招收人是不是创立者、有没有招收过自己；招收人没组织则自己的组织号也抄成 0）；组织号 0/越界 → 静默；否则自己 jyid 追加到该组织的成员数组（**已经在里面也照追加**，所以重复加入会有重复项），**全服**收 S2C 0x55 = 自己 jyid + `01` + 组织号(LE16)。原来的组织不处理：创立者自己去加入别的组织后，他仍在自己组织的成员数组里 |
| 0x4F 07 列表 | `07`（后面随意） | 组织号 0/越界 → 静默；否则自己收 S2C 0xAD = `10` + 每个**在线的、不是自己的**成员一项 `05 名字长度 名字(BIG5)`（成员数组里重复就列重复；一个人都没有就只有 `10`） |
| 0x50 踢人 | 4 字节（不看）+ 对方名字（BIG5 字节，必须和在线玩家的名字完全一致），至少 1 字节 | **不检查是不是创立者**，谁都能踢任何在线玩家。找不到名字 → 自己收 0x1A「此玩家不在線上﹗」；自己组织号 0/越界 → 静默；否则从**自己组织**的成员数组里删掉对方（第一个；不在里面也行），对方组织号 := `" 0"`，**全服**收 S2C 0x56 = 自己 jyid + 对方 jyid |
| 0x51 退出 | `01` | 组织号 0/越界 → 静默；否则从成员数组里删掉自己（第一个），组织号 := `"0"`，**全服**收 S2C 0x57 = 自己 jyid。创立者退出不会解散组织也不换创立者（只是他的组织号成了 0，没法再招收） |
| 0x56 查询 | 子类型 06 / 04 / 05 | 自己收 S2C 0x39（长帧）= `05` / `03` / `04`，固定值，和组织状态无关（没组织的人也一样）；其他子类型静默。含义没追（多半是组织战 / 升级之类还没开放的功能的返回码） |
| 0x02 子类型 05 组织聊天 | `05` + 内容（至少 1 字节） | 发给自己组织成员数组里的**每一项**中在线的、不是自己的人（重复项收重复），S2C 0x04 = `05` + 发送者 jyid(LE32) + 内容；**不扣饮食饮水**（公共聊天才扣）。自己组织号 0/越界（含被踢的人）→ 静默。发送者不回显 |

## 没做 / 不确定

- 0x54 的 1802 字节模板是原版程序里的一段常量（含进程内存残留的地址之类），逐字节照抄到 `data/org_recruit_template.hex`；真客户端怎么解析它没验证（客户端看起来只用前面的创立者 jyid / 名字 / 组织号）。
- 帧头长度字节：原版 0x54 固定写 `18 07`（=1816），实际载荷随组织名长度变化，新服务端按实际长度编码。
- 组织名长度上限、名字里含 `00` 之类没测（实测 60 字节、`ff fe` 都能创立）。名字超过 255 字节时 0x54 / 0x4F 的长度字节会怎样没测。
- 组织的玩法（组织战、组织仓库、等级……）一概没碰；`zuzhi` 表原版也不用。
- 原版重启后组织全没，新服务端同样只放内存。
