# 聊天、移动、上下线广播（实测 + 反编译）

方法：`tools/multi_probe.py` / `tools/move_probe.py` / `tools/enter_probe.py` 对本机原版服务端同时登录两个测试号，
让一方发指令，记录双方收到的帧；聊天分支的结构由 `0x72e01f` 的反编译确认。新服务端实现在 `jyserver/server.py`，
对同样的流程输出与原版一致（2026-10 同时连 6731 / 6732 对照）。

## 公共聊天：C2S 0x02（不是 0x04）

旧笔记把聊天记成 `0x04`，是因为 S2C 转发用的是 `0x04`。反编译 `0x72e01f`（派发表里 02/03/04 都进这个函数，
按第 4 个令牌分支）：

| C2S | 含义 | S2C 转发 |
|---|---|---|
| `0x02` 子类型 `01` | 公共聊天（服务端 UI 标签「全屏」） | `04 01 <发送者jyid LE32> <文本>` |
| `0x02` 子类型 `05` | 组织聊天 | `04 05 <发送者jyid LE32> <文本>`，发给自己组织成员数组里每一项中在线的、不是自己的人；不扣饮食饮水（已实现，见 `docs/组织.md`） |
| `0x03` | 私聊，目标按名字查找 | `04 03 <名字…> <文本>`，长帧（未实测） |
| `0x04` | 「轻频」聊天：`N` + `N×4` 字节 + 文本 | `04 07 …`（实测没触发，条件不明） |

公共聊天细节（实测）：

- 载荷 = `01` + 文本字节，**原样转发**，不转码（BIG5 字节、空格、`00` 都原样）。S2C `0x04` 短帧，发给**除发送者以外**所有在线玩家（不分地图）。
- 发送者每发一句，**饮食、饮水各 −5**（到 0 为止；反编译：值 −5 ≤ 0 就置 0），随后收到两条 `0x7B`（长帧）：
  `34 01 <新值 LE32>`（饮食）、`36 01 <新值 LE32>`（饮水）。
- 更正：早先看到的「原版偶尔静默丢掉某句聊天」不是服务端行为，是模拟客户端没有跟着服务端的换密钥帧（`0x33` + `0x99 04 <种子>`）
  改 C2S 密钥，指令被当成乱码忽略了，见 docs/药品效果.md。
- 反编译里还有答题活动（`DAT_00dd8a9c == 1` 且玩家 `+0x60 == "3511"` 时聊天被当成答题答案）、
  组织/轻频聊天等，都没做。

## 移动：C2S 0x06

- 载荷 = 起点 X、Y、终点 X、Y（LE16×4）+ 3 字节未解。
- **原版不校验**：起点对不对、步长多大（试过 1 到 450）、尾部填什么（`000000` / `010203` / `ffffff`）都照收。
  服务端把终点记为新位置，回显 S2C `0x06` 短帧 = `jyid(LE32)` + 那 8 字节。
- 回显给**同一张地图**上的在线玩家（含自己）。不同地图的玩家收不到——这是一次双人实测推断出来的，
  没有细测范围（有没有视距限制不知道）。
- 位置会保存：下线再登录，登录序列里的 `0x08` 就是最后一次移动的终点。

## 上下线广播

别人上线时，其他在线玩家（不分地图）依次收到：

1. `0x60`（短帧，46 字节）= jyid + 名字(17) + 称号(17) + 8 字节（样本全 0）
2. `0x14`（长帧）子类型 `08` +「玩家﹕」+ 名字 +「上線了」
3. `0x02`（短帧，96 字节）= jyid + 地图/x/y（LE16×3）+ `01` + 名字(17) + 称号(17) + 6×`00` + `01 01` + 头盔/衣服/武器（LE16×3，对应 renwu.toukui/yifu/wuqi）+ 补零 + 末字节 `32`
4. 如果上线的是总消费点数全服第一的号：再加 `0x14` 子类型 `0e` 的「本服贊助王﹕…」广播

下线时：`0x05`（短帧）= jyid + `00`，随后 `0x14`（长帧）子类型 `08` +「玩家﹕」+ 名字 +「离開游戲」。

反过来，**新上线的人**登录序列里没有「已在线的人」的外观包（实测：A 在线，B 在别的地图上线，B 的 18 帧序列与单独登录一样）。
同地图时会补发：登录序列里 0x31 之后多出每个在线者的 0x02 + 0x82，见 docs/传送与地图可见性.md。
