# 组队：0x26 创建 / 0x2C 邀请 / 0x2D 应答 / 0x2E 队伍聊天 / 0x27 解散 / 0x29 离队

方法：反编译 `0x8d4405`（26）、`0x8d4d37`（2C 和 2D 共用）、`0x8d5ab3`（2E）、`0x406641`（27）、`0x408855`（29 和下线时的离队），
再用三个模拟客户端 A=8617293、W=1234567（地图 2200）、C=123456（地图 2801）对原版逐条验证（`tools/multi_raw.py`、`tools/team_compare.py`）。
新服务端 `jyserver/team.py`；`tests/test_team.py` 期望值来自原版回包；`tools/team_compare.py` 的 9 套场景（共约 180 行回包）对原版和新服务端各跑一遍，逐行一致。

## 原版的数据结构（新服务端照搬）

- 每个玩家一个**队伍号**（`player+0x3c0`，0 = 没队伍）。
- 全局的队伍数组，每个队伍是 **7 格**的数组（存玩家，0 = 空），**格 0 是队长**。新建队伍总是追加新的一项，解散只是把格子清空，号码不回收。
- 「队伍号等于 X 的人」是发包的筛选条件，所以**队伍号 0 就是「所有没组队的人」**——没组队的人发队伍聊天 / 离队，会让所有没组队的在线玩家收到。

## 指令

| C2S | 载荷 | 行为 |
|---|---|---|
| 0x26 创建 | 任意（原样回显） | 当前地图是 **3511 / 1820 / 13000** → 自己收 0x1A「當前地圖不能組隊」。否则新建队伍（自己在格 0，不管原来是否已在队伍里；旧队伍里的格子照旧残留），**全服**收 S2C 0x2A = 队长 jyid + `01 00` + 载荷原样 |
| 0x2C 邀请 | 对方 jyid（小端，取前 4 字节，不足补 0） | 对方在线（可以是自己、可以在别的地图、不要求有队伍）→ 对方收 S2C 0x2E = 邀请人 jyid。对方不在线静默 |
| 0x2D 应答 | 子类型(1) + 邀请人 jyid(前 4 字节)…，至少 2 字节 | 子类型 ≠ `01` = 拒绝：**只有自己**收 0x1A「對方拒絕加入隊伍」。`01` = 接受：邀请人所在队伍的号码取自**邀请人当前的队伍号**；不在同一张地图 → 自己收「地圖不同,不能組隊」；占第一个空格（格 0 起，7 格满了 → 自己收「組隊失敗,隊伍已經滿員!」）；成功后自己的队伍号 = 邀请人的，**全服**收 S2C 0x2F = `01` + 自己 jyid + 应答载荷第 2 字节起原样。**邀请人没有队伍时原版崩溃**（两次），新服务端静默。原版还有个「對方繁忙中,無法加入」，条件是邀请人的 `+0x284` 状态串 ≠ `00`（战斗之类），新服务端没有这个状态。不需要真的收到过邀请——知道队里任何一个人的 jyid 就能加入 |
| 0x2E 队伍聊天 | 4 字节（被原版吃掉）+ 内容 | 队伍号和自己相同的人（含自己）收 S2C 0x1C = **载荷去掉前 4 字节**后的原样字节（不足 5 字节就是空）。没队伍的人发 → 所有没队伍的人收到 |
| 0x27 解散 | | 队伍里**任何人**都能解散：**全服**收 S2C 0x2B = 发起人 jyid；队长（格 0）、其余各格、发起人的队伍号全清 0，队伍的格子清空。没队伍静默 |
| 0x29 离队 | | 在队伍里：在**格 1–6**里找自己（**格 0 不找**——队长离不开），找到就清格、队伍号归 0、**全服**收 S2C 0x2D = 自己 jyid。然后**不管有没有队伍**，原队伍号的人（已不含离队的自己）收 0x1A「玩家:<名字>脫离隊伍」（名字 BIG5；没队伍 → 所有没队伍的人收到） |

## 下线

玩家下线时：在队伍里 → 队长（格 0）走**解散**（全服收 0x2B，其他人队伍号清 0），其他人走**离队**（全服 0x2D + 队内 0x1A），之后才是平常的 0x05 / 0x14「离開游戲」；
没队伍的人下线什么都不多发。

## 没做 / 不确定

- 满员文字「組隊失敗,隊伍已經滿員!」和「對方繁忙中,無法加入」没能在原版上触发（要 7 个人 / 战斗状态），字节是按已验证的转换（`to_big5`）推的。
- 同一个玩家加入同一队伍两次会占两格（原版如此），离队只清第一格但队伍号归 0。
- 组队之后的玩法（队伍经验分配、队伍里的战斗、队员位置同步）没碰；战斗那边 `组队中不得瞬移` 之类检查也没有。
- 原版的 S2C 0x2A 帧头长度字节固定 `0E`，载荷长度变化时它和实际长度不一致，新服务端按实际长度编码。
