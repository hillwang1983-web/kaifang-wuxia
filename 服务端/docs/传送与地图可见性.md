# 传送 0x5D 与地图可见性

方法：`tools/multi_probe.py --a 8617293 --b 1234567 --c 123456 --login-detail` 同时登录三个号（分别在地图 2200 / 8105 / 2801），
让 B 传来传去，记录三方各收到什么。新服务端（`GameServer.on_teleport`）对同一套 7 步传送序列的输出与原版逐字节一致
（除 0x08 末尾的随机字节）。

## C2S 0x5D：地图(LE16) x(LE16) y(LE16)

原版**不做任何校验**（不查地图是否存在、坐标是否合法、有没有传送物品），直接传。多余的尾字节忽略。

传送者自己收到：

1. `0x08`(长帧) = 地图 x y（LE16×3）+ 1 字节随机值（实测一直在 2..9）
2. 四个空载荷长帧：`0x02`、`0x6D`、`0x3D`、`0x31`（和登录序列里同一组）
3. **仅当换了地图**：新地图上每个已在线的人，各发 `0x02`（96 字节外观/位置包，位置是此人当前位置）+ `0x82`（短帧，jyid + `00 00`）

其他人：

- 原地图上的人收到 `0x62`(短帧) = jyid（谁离开了）
- 新地图上的人收到 `0x61`(短帧，54 字节) = jyid + 地图/x/y（LE16×3）+ `01` + 头盔 衣服 武器（LE16×3）+ 2 字节来源不明（见下）+ 补 0 + 末字节 `14`
- **传送到同一张地图**（换个坐标）：同图的人先收到 `0x62` 再收到 `0x61`（先走再来）；传送者自己不收对方的外观包

其他地图上的人什么也收不到；聊天（C2S 0x02）依旧发给全服。

## 登录时就在有人的地图上

登录序列和平时一样，只是在 `0x31` 之后、`0x2F` 之前，**图上每个已在线的人**多出 `0x02` + `0x82` 两帧（顺序按上线先后，
实测一人）。已在线的人只收到常规的上线三件套（0x60 / 0x14 / 0x02），**不会**收到 `0x61`。

## 位置保存

传送的目的地同样记入角色（renwu.map / x / y），下线时存库，下次登录从那里开始（原版实测：下线重登，`0x08` 就是最后一次传送/移动的终点）。

## 外观包里武器后面的 2 字节 = 善恶值

0x02 偏移 59、0x61 偏移 17：**有符号 LE16 的 `evil_val − 2000`**（2000 是中性）。123456 的 evil_val=2400 → `90 01`（+400），
8617293 / 1234567 的 2000 → `00 00`。证据：把 123456 克隆成 8 份、每份清零一组列，只有清零
「combat_exp / kill_val / evil_val / fame_val / online_time / jy_money / study_count」那份变成 `30 f8`（−2000）；
与地图、赞助点数、六件装备、六维都无关。7 个列里是 evil_val 而不是别的，是因为 2400−2000=400 恰好吻合，
并且清零后 0−2000 恰好是 `30 f8`——两个数同时对上。

## 未解
