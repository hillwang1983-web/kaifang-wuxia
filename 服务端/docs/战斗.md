# 战斗（单人打怪，2026-10-19）

`jyserver/battle.py`，由 `server.py` 的 `0x30 / 0xE3 / 0xD7 / 0xD4 / 0xD8 / 0xE5 / 0xE6 / 0xDE / 0xF9` 调用。**这一块一半对过原版，一半是按客户端侧反编译 + 自己定的数值**，下面分开写。
网页客户端（`客户端\逆向工具\jyclient.py` 等）已经能和它打完整的一场：`tests/test_battle_e2e.py`。

## 按客户端侧反编译做的（没对过原版）

原版需要正确的尾部校验字节才肯处理 `0xE3` / `0xD7`（我们没有校验表），所以进战之后原版一律静默，没法对照。依据是 `客户端\逆向工具\战斗协议_客户端侧.md` §8：

1. `0xE3`（进战，已有遭遇）→ `D5`(我方 `14 09`) `D5`(敌方 `55 08`) `D4`×敌(`实体id 列 行`) `DC`(敌方气血) `C6`。
2. `0xD7`（28 字节）：先把前 16 字节原样转发（S2C `D7`）。施术者是自己 → 打 `[11][12]` 格上的敌人（没有就第一个活的）：`D8` `01 <敌id> <新气血>`；敌人气血到 0 → `E6 <敌id>` →（掉落则 `E4 列 行 物品` → `77` → `E8 <jyid> 列 行`）→ `7B 2b`（实战）。施术者是敌人（客户端替怪发）→ 打玩家：`D8` `01 <jyid> <气血>` + `7B 18`。校验字节、反作弊计数、`[13][14]` 混淆值都不验。
3. 战斗结束由客户端判胜负，约 15 秒后上报 `E5`；服务端只按自己的气血回 `81`。
4. `0xDE`（防禦 7 / 閃躲 8 / 養精蓄銳 9 / 自動 11；`jyid(LE32) 命令号 计数器(LE32) 校验`，10 字节）：已进场且活着 → 回 `D7` = `<jyid> <命令号> 00×11`（出招转发的同形，**自拟**；原版没有正确校验字节就一律静默。我对着原版把 E3 的尾字节 0–255 全试了一遍（列行 5,6，模式 1）没有一个有回应，校验字节还跟列 / 行 / SEED 有关，没解）。没有防御、闪躲、回气的数值效果。

## 自己定的数值（原版公式在 `0x52d598`，一百多万字符的反编译，没读）

- 怪：MOB数据.csv 的 HP / 攻 / 防 / 实战。**一次遭遇几只**是我加的扩展：`0x30` 的 19 个填充字节里**第一个**字节 = 同种怪的数量 1–5（原版客户端填零 → 1 只；0、>5 都当 1 只），实体 id 依次加 1e5（槽位 +1），站位见 `ENEMY_CELLS`。
- 玩家伤害 = (武器强度 + 臂力×3 + 武功「攻」×(1+等级/200)，没武功按 100) × 16 × 随机(0.9–1.1) × 150/(150+怪防)。
- 怪伤害 = 怪攻 × 随机(0.8–1.2) × 2 × 200/(200+防具强度+根骨×2)。
- 掉落：NPC掉落.csv 里该 mob 的 A–F 非 0 项随机一件，按「掉宝率」%；物品进背包。
- 奖励：杀死怪时加 MOB数据.csv「实战」到人物的 `combat_exp`（`7B 2b`）。
- 没做：高等级号的死亡惩罚（掉实战 / 掉武功 / 替身娃娃）、队伍参战、混合多种怪、战役事件的胜负分支、狂状态、反作弊；怪死后的刷新、刷新点校验由客户端自己管（服务端不记、不校验）。

## 回答客户端侧的几个问题

1. SEED：我们没有，`D7` 的 `[13][14]` 不还原，用 `[11][12]`；`D4` 原样回显。原版 `D4` 密钥 = 个人底数 + 最近一次 `D1` 随机数（见上），多半就是那个 SEED，但具体公式没对出来。
2. `E5` 载荷：原版收 `jyid(LE32) + 1 字节`，甚至不看内容（短载荷也回）。
3. `D5` 的 A/B：原版实测只见到 `55 09`（小实体遭遇）；进战后的 `55 08` / `14 09` 来自客户端侧抓包记录，我们沿用。
4. 怪 AI：接受客户端替怪发的 `D7` 并算伤害（不自己跑 AI）。
5. 其余未解包（`D3 D6 D9 DB DD E0–E3 E9 EA EF`、`C2S D4/D8/DF…`）：除 `EF`(拒绝) 和 `D8/D4` 的上述几条外，都没做。`DE` 和 `F9` 已做（见上）。

## 原版战斗处理函数 `0x40db88` 的分支（2026-10-20 读反编译 + 对原版实测）

处理函数按 `T[3]`（opcode）依次比较，顺序：`30`、`DA`、`F5`、`D7`、`DF`、`D8`、`F9`、`E5`、`E6`、`D3`、`E3`、`DE`、`D4`…（反编译文件 `scratch/battle.c`）。

| C2S | 门槛 | 做了什么 |
|---|---|---|
| `D7`（总令牌数 > 30，即载荷 ≥ 27 字节） | 玩家存在；`T[4..7]` 拼成的数 = 自己的 jyid 才走玩家路径 | **只记录，不回包、不算伤害**：把施术信息存进玩家对象（武功号取自 `T[10..13]`、命令号 `T[8]`、格 `T[15] T[16]`、`T[20..23]`），在玩家武功表 `+0x170` 里找这门武功取等级（找不到也继续）；在队伍里（`+0x150` 非空）就把整条转发给队友；个别内功（九阳 / 易筋经…按 `+0x124` 武功号）改 `+0x468` / `+0x46c` 计数并给全队发一条 `1A 64` 文字。**没有任何对尾部校验字节的检查** |
| `DF`（令牌数 > 15） / `D8`（令牌数 > 15） | 玩家的 `+0x284` 状态串必须 = `02`（**0x30 遭遇成功后置的「战斗中」**），否则回 `EF <jyid> 10`；`DF` 另查「攻击间隔」`< 0x514`（1300 ms）→「禁止开快招」 | 按玩家身上的模式标志（`+0x17c / 0x180 / 0x184 / 0x188 / 0x18c / 0x190 / 0x194 / 0x198 / 0x19c / 0x1a0 / 0x1a4 / 0x2fc / 0x324 / 0x474 / 0x478`）分派到各战役 / 玩法的结算函数；**全是 0（普通遭遇）→ `FUN_0052d598`**（那个一百多万字符的大函数，伤害 / 掉落 / 经验 / `D8` 气血清单都在里面）。对原版实测：遭遇后 `DF` 载荷 `jyid + 10 个零` → `D8 01`（空清单，因为服务端内存里没有怪实例）；`D8` 载荷 `jyid + 9 个零` → 静默（全零载荷才回 `D8 01`，原因没追） |
| `F9` | 无 | 逃跑：**随机(1–100) < 40 + 玩家`+0x23c`/10（再按某门武功加成）** → 单人（`+0x3c0` 队伍号 0）回 `F9 01`，否则 `F9 00`；组队时让队长 / 队友判定。`+0x23c` 是哪个属性没查出来，测试号上表现为约 39% |
| `E3` | 在队伍里 | 只把 `E3 <jyid> 列 行` 转发给队友；**单人什么都不回**（设计如此，不是校验字节问题） |
| `E5` / `E6` | 无 | 照 `docs/战斗.md` 上面的实测：`81 82 E6 7B 18` |
