# 新建角色（还没有角色的账号第一次进游戏）

方法：在原版数据库里手工插一行 `account`（原版对完全不存在的账号**既不回包也不建号，直接断开**），然后用
`tools/create_probe.py` 走完整个流程，再读库、对比登录序列。反编译来源：`0x60bcd7`（C2S 0x20）、`0x60cc0e`（C2S 0x19）。
新服务端（`jyserver/creation.py` + `GameServer.on_create / on_start_login`）对两个不同的新号（不同出生地图、头像、属性、
生日）的 18 帧登录序列逐字节一致（仅 0x1E 开头的计数器和 0x08 末尾随机字节不同）；
`tests/test_creation.py` 还拿原版为 9999013 建出的角色（`data/fixtures/char-9999013.json`）逐列、逐字节对照。

## 流程

1. **C2S 0x01 登录**，账号存在但还没有角色 → 回**另一条握手**（"模板 A"）：整帧 33 字节、**没有尾部 `00`**，
   载荷 `01 a2 bc 08 5f 0c 25 26 77 65 6e 21 65 6c 6f 72 2a 32 03 2e 2e 2e 17 12 15 14 12 13 15`。
   已有角色的账号收到的是 34 字节 + 尾部 `00` 的模板 B（密钥 0x7D）。
2. **密钥换成 0x34**：模板 A 的种子 `a2 bc 08 5f` 经 `derive_key` = **0x34**，此后 S2C 帧都用 0x34，
   C2S 密钥 = `0x34 XOR 序号`（用 0x7D 的帧原版一概不理）。这是 `derive_key` 公式（常数项 145）的第二个实测验证点
   （第一个是模板 B 的种子 `a2 bc 28 37` → 0x7D）。
3. **C2S 0x76 摇点** → `0x5A`（长帧）= `03` + 7 个 15..25 的数，总和 140。可以反复摇；摇的结果**不存库**，
   最后由客户端在长 0x19 里把选好的属性带回来。
4. **C2S 0x20** 载荷 = 1 字节（含义未知，实测发 `00`）+ 名字字节（GBK）。名字已被某个角色占用 → 回 `0x25`(短) `01`；
   否则回 `0x25` `00`，并 `insert into renwu (jyid,name)`、`char_equip`、`jineng`、`ypsx`、`zssj` 各一行——
   **只写 jyid 和名字，其余列全靠表结构的 DEFAULT**（`data/defaults.json`，由 `tools/dump_defaults.py` 从库导出：
   气血 2000、精神 210、内力 1、饮食饮水 100、金钱 100000、善恶 2000、jmkey 125 …，map/x/y/六维/性别都是 0）。
5. **长 0x19**（载荷不是 1 字节）。只有本连接里刚建好角色、还没进过游戏的号才接受；已有角色的号发这个，
   原版记日志（`\jilu\日期.txt`）并断开。布局：

   ```
   [0]            未知（实测发 00）
   [1:3]          出生地图 LE16（e8 0c = 3304）
   [3]            名字长度 N     [4:4+N]       名字
   [4+N]          昵称长度 M     [5+N:5+N+M]   昵称
   之后 11 字节    臂力 胆识 悟性 富源 定力 机敏 根骨 | 头像 | 模式 | 生日月 | 生日日
   ```

   校验：长度不够、或 7 项属性总和 > 145 → **静默放弃**（无回包、不断开）。通过后原版逐列 `update renwu`：
   map、name、nickname、head_image、mode、b_month、b_day、str crg wint luk dex agi vit；
   **sex = 1（头像 1..4）否则 2**；ysbili/yswuxing/ysjimin/ysgengu = 臂力/悟性/机敏/根骨（原始属性备份）；
   `account.state = 1`；**出生坐标按出生地图硬编码**：3304→(702,386)、8105→(1346,462)、1305→(751,461)、
   2802→(447,475)（别的地图不改，保持 0,0）；再按 `config/新人上线.ini` 给**新人物品**（实测 12 行：
   18072 15080 14056 13066 48022 48631 12130 11047 27058 26028 各 1、58182 ×10、40145 ×1，每种一行，`state=200`）。
   然后照常发 18 帧登录序列。
6. 之后同一账号再登录，库里已有角色，走模板 B。

## 新服务端怎么建号

原版靠外部的注册站往 `account` 表插行。新服务端用命令行：

```bash
python -m jyserver.manage add-account 9000001 mypassword
```

首次登录该账号就会走上面的流程。

## 未解

- 长 0x19 的第 0 字节、0x20 的第 0 字节含义。
- `config/新人上线.ini` 里的「商城点数=100000」：实测新号的 `account.shangchengdianshu` 仍是 0，不知道哪里用。
- 「重建角色失效物品」（28290 武曲祝福丹）：原版在玩家状态 `+0x470 == 1` 时额外发，这个标志什么时候置位没查到
  （测试号 8617293 背包里有它，说明它是重建过角色的号）。新服务端不发。
- 账号 `state`：新号初始该是 0 还是 1？实测手工插入的账号用 1。原版对 `state=0` 的账号的回复没测过。
- 0x1E 开头的 4 字节计数器**不是**服务端运行分钟数：原版实测约每 76 秒 +1（818 → 821 用了 4 分钟），起点和单位不明
  （可能与「时间倍数」配置有关）。新服务端暂时按运行分钟数发。
