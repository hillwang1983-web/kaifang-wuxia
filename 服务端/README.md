# 网金复刻（路线 B）

目标：用高级语言（Python 3.14 + asyncio）重写《金庸群侠传Online》私服服务端，
**原版客户端 `loginp.exe` 能直接连上**，之后可以自由增加功能。个人学习自用，不分发、不商用。

原版文件：`C:\游戏\网金最原始文件\网金最原始文件\`（客户端、服务端.exe、data、config 都在里面，只读，不要改）。
旧项目 `C:\游戏\新网金`（网页版，已封存）是参考资料，本项目不依赖它的代码。

## 现状：M0 完成；M1 登录、聊天、移动、装备物品、传送、新建角色、商店、事件引擎（简单事件）、钱庄、丢弃 / 回收 / 交易已完成（278 个测试通过）

**新服务端** `jyserver/server.py`：asyncio TCP，说原版协议。已实现：登录握手（`01`，按角色库校验明文密码，
`state=0` 的号拒绝）、摇点（`76`）、启动登录（`19`，**登录序列由角色数据生成**，不再回放），
以及原版的 C2S 密钥规则（`0x7D XOR 序号`）、防重放、密钥不对的帧静默忽略。
**三个测试号（8617293 / 1234567 / 123456）在新、旧服务端上登录，回包逐字节相同**（只差运行分钟数和一个随机字节；
2026-10 用 `tools/sim_client.py` 同时连 6731 / 6732 实测）。

```bash
python -m jyserver.importer                 # 先把原版 MySQL 里的角色导入 data/chars.sqlite（只读 MySQL）
python -m jyserver.server --port 6732        # 默认 6732，和原服务端并存做对照
```

**用原版客户端连它**：客户端连的是固定的 6731 端口，所以要先停掉原版服务端和抓包代理，再
`python -m jyserver.server --port 6731`。

- `jyserver/state.py`：登录序列生成器（`0x1E` 角色状态包等）。`jyserver/store.py`：SQLite 角色库。`jyserver/importer.py`：MySQL → SQLite 导入。
- `tools/multi_probe.py` / `move_probe.py` / `enter_probe.py`：对原版同时登录多个号，看聊天、移动、上下线时各方收到什么。`tools/va_bytes.py`：按虚拟地址直接读 服务端.exe 里的常量字符串。
- `tools/pseudo_branches.py` / `condense_pseudo.py`：把 REA 导出的超大反编译伪代码压缩、列出 opcode 分支骨架。
- `tools/verify_state.py`：生成器 vs 真实快照（`data/fixtures/char-*.json`）逐字节对比。`tools/build_s2t_nls.py`：用 Windows NLS 生成简繁表 `data/s2t.json`（2191 字）。

- `jyserver/codec.py`：帧的编码/解码、流式拆帧、密钥推导。**无状态解码**，编码需调用方给对密钥。
- `jyserver/opcodes.py`：已知 opcode 表（只收有证据的，每条标证据等级）。
- `jyserver/text.py`：BIG5 / GBK 字节串互转（简繁转换在 `state.to_big5`）。
- `tools/jyproxy.py`：夹在原客户端和原服务端之间的 TCP 中转代理，逐块录 JSONL。
- `tools/analyze_session.py`：分析录像，按连接/方向拆帧，输出 opcode 统计和时间线。
- `tools/decode_hex.py`：命令行解一段十六进制。
- `tools/sim_client.py`：**模拟客户端**。`--probe 19:00` 即登录并「启动登录」，原服务端会回完整登录序列；`--dump-json` 把回包存成夹具。
- `tools/key_probe.py`：黑盒探测 C2S 密钥（对每个密钥字节发一次探针，看服务端是否处理）；结论见 `docs/服务端逆向笔记.md` 第五轮。
- `data/fixtures/login-8617293.json`：**原版服务端对登录的真实回包（19 帧）**，新服务端的第一个对照基准；`tests/test_fixture.py` 校验编解码器能逐字节还原它们。
- `tools/fake_client.py`（旧，密钥规则已过时，保留作参考）：模拟客户端，只发登录包（可用 `--then`/`--after-key` 追加帧），把原服务端的回包解出来；通过抓包代理连，双向字节都会被录下。
- `tools/flow_outline.py`：把一个处理函数的汇编压缩成「流程大纲」（引用的 SQL、S2C 常量、发包/断开调用，按地址顺序）。
- `tools/dispatch_map_from_asm.py`：从 REA 导出的 `0x5f8f04` 汇编里提取「C2S opcode → 候选处理函数」表 → `data/c2s_dispatch.json`（启发式，未全部验证）。
- `tools/extract_templates.py`：从 `服务端.exe` 提取内置的 77 条明文 S2C 封包模板 → `data/s2c_templates.json`、`docs/服务端内置封包模板.md`。
- `tools/exp_compare.py` + `tools/exp_scenarios.py`：把任意「结果」语句临时写进原版 `事件.csv`（地图 8、id 50001 起），重启原版后在 8617293 上触发，对原版和新服务端逐帧、逐库比较（`--original` 只看原版，`--cleanup` 还原 事件.csv）。
- `tools/event_probe.py`：事件探针，对原版（`--target mysql`）或新服务端（`--target sqlite:<库>`）按脚本发 0x6B / 传送 / 原始指令，记下回包和每次下线后的库状态（`--json`）；`--create 名字` 走新账号流程建角色，`sql:` 步骤在两次登录之间改库。`tools/compare_event_logs.py` 比较两份记录。
- `tests/`：17 个测试（样本取自旧项目的协议笔记，往返测试单独标注）。
- `docs/协议模型.md`：帧模型 + 证据等级 + 未解决项。 `docs/服务端逆向笔记.md`：服务端.exe 的函数定位。

## M1 第一步：重新抓一份完整的登录到进图会话

旧的抓包数据已经丢了，需要重新抓，作为新服务端的对照基准。**这些要你在本机手动操作**：

1. 启动 MySQL：`服务端\MySQL启动器.bat`（`netstat -ano | findstr 3306` 确认端口在监听）。
2. 确认 `客户端\maina\server.ini` 里是本机当前的局域网 IP（GBK 编码），不能是回环地址。
3. **先**启动代理：`python tools/jyproxy.py`（自动探测局域网 IP；记下它打印的 IP 并核对和 server.ini 一致）。
4. **后**启动 `服务端\服务端.exe`。
5. 启动客户端，登录测试账号，进入游戏，走几步，退出。
   ⚠️ `登录器(双).exe` 是卖家的第三方程序，逆向笔记推测它会向 `loginp.exe` 注入 `wj.dll`，
   `wj.dll` 里有远程 txt 地址和硬编码的邮箱凭据（未经动态验证）。建议在虚拟机或隔离环境里运行；
   能否直接启动 `maina\loginp.exe` 绕开它，还没验证。
6. 关掉代理（Ctrl+C），录像在 `captures/` 下；`python tools/analyze_session.py captures/xxx.jsonl --timeline` 查看。

录像含账号 ID，`captures/` 已加入 .gitignore。没有安装 git，目前没有版本管理。
